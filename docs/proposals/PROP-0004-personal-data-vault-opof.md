# PROP-0004: Personal Data Vault ตามแนว OPOF

- สถานะ: Covered — ใช้ ADR 0006/0007 เป็นหลัก
- วันที่: 2026-09-29
- ระยะ: P0
- ผู้ตัดสินใจ: (รอกำหนด)

> **เทียบกับระบบจริง (monorepo `spada-monorepo` @ `206d1f9`, 2026-09-29):** ADR 0006 (OPOF, OMOF, Five Books), ADR 0007 (OMOF/OPOF semantic equivalence), ADR 0005 §13 (การลบข้อมูลและ legal hold) · `services/opof-service` · ข้อเสนอนี้ซ้ำกับของจริง
> ข้อเสนอนี้ร่างก่อนเห็นระบบจริง เนื้อหาด้านล่างคงไว้เป็นบันทึกตั้งต้น ให้ยึด ADR จริงเป็นหลัก ดู [CURRENT-STATE](../CURRENT-STATE.md) และ [GAP-ANALYSIS](../GAP-ANALYSIS.md)

## บริบท
ข้อมูลควรอยู่กับเจ้าของและไม่ข้ามเจ้าของ แต่เรื่องร่วมหลายคน (shared matter) ต้องจัดการโดยไม่ละเมิดขอบเขต

## ทางเลือกที่พิจารณา
1. คลังกลางร่วม
2. แฟ้มรายบุคคล (OPOF) + OMOF/Participant Evidence Projection สำหรับเรื่องร่วม

## การตัดสินใจ (ข้อเสนอ)
เลือกข้อ 2: หนึ่งคนหนึ่งแฟ้ม จัดชั้นความอ่อนไหว เข้ารหัสด้วยกุญแจเจ้าของ เรื่องร่วมแยกเป็นแฟ้มกลางพร้อม projection ต่อผู้เกี่ยวข้อง และมี artifact พิสูจน์ว่าไม่มีข้อมูลข้ามเจ้าของ

## ผลที่ตามมา
ข้อดี: ลดผลกระทบเมื่อรั่ว ควบคุมสิทธิ์ชัด ข้อเสีย: ค้นหา/วิเคราะห์ข้ามคนยากขึ้น ต้องใช้ consent-based query หรือ privacy-preserving analytics

## เกณฑ์ตรวจรับ
- ตรวจอัตโนมัติว่าไม่มีข้อมูลข้ามเจ้าของ
- เจ้าของ export แฟ้มครบได้
- shared matter ผ่านการตรวจ projection

## คำถามที่ยังเปิดอยู่
- เจ้าของแฟ้มกรณีผู้เสียชีวิตหรือไร้ความสามารถ
- นโยบายสำรองข้อมูลโดยไม่ทำลายหลักการ
