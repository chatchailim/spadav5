# แผนงานปรับปรุงสถาปัตยกรรม SPADA Node/Network + OneManOS SetBox เพื่อ Digital Economy

> สถานะ: ร่าง v0.1 (Draft) · วันที่: 2026-09-29
> หมายเหตุ: repo นี้เริ่มต้นว่างเปล่า เอกสารนี้จึงเป็นข้อเสนอเชิงหลักการ ต้องตรวจเทียบกับสถาปัตยกรรมปัจจุบันจริงก่อนอนุมัติ (ดูหัวข้อ 9)

## 1. บทนำ

เป้าหมายคือทำให้มนุษย์เป็นเจ้าของอำนาจ ข้อมูล และคุณค่าของตนเองใน Digital Economy โดยระบบต้อง **พิสูจน์ได้** ไม่ใช่เพียงสัญญาว่าจะทำ เอกสารนี้กำหนดหลักการ ชั้นสถาปัตยกรรมที่ควรเพิ่ม แผนทยอยทำ เกณฑ์ตรวจรับ และความเสี่ยง

## 2. Constitution: หลักการออกแบบ 5 ข้อ

1. **Human sovereignty** — กุญแจ ข้อมูล และการตัดสินใจสุดท้ายเป็นของมนุษย์ ผู้ให้บริการและ AI ไม่มีสิทธิ์ขาด
2. **Verifiable, not trusted** — ทุกข้ออ้างต้องมีหลักฐานที่ตรวจสอบได้โดยไม่ต้องเชื่อผู้ให้บริการ
3. **Graceful degradation** — ทำงานแบบ offline/กระจายศูนย์ได้ ไม่ล่มทั้งระบบเมื่อจุดใดล้ม
4. **Least data, most utility** — เก็บข้อมูลน้อยที่สุดที่จำเป็น พิสูจน์แทนการเปิดเผย
5. **Inclusion by default** — ผู้ใช้มือถือเครื่องเก่า ไม่มีอินเทอร์เน็ต หรืออ่านหนังสือน้อย ต้องใช้ได้

## 3. SPADA Node/Network: ชั้นที่ควรเพิ่ม

| ชั้น | ข้อเสนอ | ประโยชน์ |
|---|---|---|
| Identity | DID + Verifiable Credentials คู่กับ KeySign, หลาย persona, ZK proof (เช่น "อายุเกิน 18") | กันการสอดแนมและรวมโปรไฟล์ |
| Key recovery | Social recovery แบบ Shamir 3-of-5, time-lock, dead-man switch (มรดกดิจิทัล) | ไม่สูญทรัพย์เพราะทำอุปกรณ์หาย |
| Trust & Consensus | Node 3 บทบาท (Validator/Witness/Relay), BFT consensus, Merkle transparency log ต่อยอดทะเบียน append-only | ตรวจสอบย้อนหลังได้ ไม่มีผู้ควบคุมรายเดียว |
| Governance | จำกัดสัดส่วน node รายเดียวไม่เกิน 1/3, เปลี่ยนโปรโตคอลผ่านการลงคะแนนพร้อม time-lock | กันการยึดเครือข่าย |
| Interoperability | W3C DID/VC, ISO 20022, gateway ไป PromptPay/CBDC | ไม่ผูกขาด ต่อกับระบบเดิมได้ |
| Resilience | Mesh/LoRa/sneakernet, store-and-forward | ใช้ได้ในชนบทและยามภัยพิบัติ |

## 4. OneManOS SetBox: สิ่งที่ควรเพิ่ม

- **Personal Data Vault ต่อคน** บนแนวคิด One-Person-One-File (OPOF): ข้อมูลอยู่กับเจ้าของ ผู้อื่นเข้าถึงได้ผ่าน consent ที่ระบุวัตถุประสงค์และหมดอายุเอง
- **Consent Ledger**: บันทึกใครขอ/ใช้ทำอะไร/เมื่อไร เพิกถอนได้ทันที สอดคล้อง PDPA
- **Personal AI Agent ภักดีต่อเจ้าของ**: รัน on-device, สิทธิ์จำกัดตาม policy, ธุรกรรมมูลค่าสูงต้องมนุษย์ยืนยันด้วย KeySign, มี audit log และ kill switch
- **Policy-as-Code ต่อคน**: เจ้าของตั้งกติกา เช่น "ห้ามขายข้อมูลสุขภาพ"
- **Capability-based sandbox**: แอปไม่มีสิทธิ์เริ่มต้น ต้องขอทีละอย่าง
- **Accessibility layer**: อินเทอร์เฟซเสียง ภาษาไทย/ท้องถิ่น โหมดผู้สูงอายุ
- **Open hardware + reproducible build**: ให้ชุมชนตรวจได้ว่า firmware ตรงกับซอร์ส

## 5. Digital Economy Layer

1. **Data dividend** — เจ้าของข้อมูลได้ส่วนแบ่งอัตโนมัติเมื่อข้อมูลสร้างมูลค่า
2. **Micropayment / programmable money** — ชำระระดับสตางค์ ค่าธรรมเนียมต่ำ
3. **Portable verifiable reputation** — ผลงานและความน่าเชื่อถือเป็นของบุคคล ย้ายข้ามแพลตฟอร์มได้ ช่วย SME เข้าถึงสินเชื่อ
4. **Open marketplace ไม่มี gatekeeper** — มาตรฐาน listing, escrow, dispute resolution ที่ตรวจสอบได้
5. **Public goods fund** — หักส่วนเล็กน้อยของค่าธรรมเนียมเข้ากองทุนซอฟต์แวร์เปิดและการเข้าถึง
6. **Anti-extraction** — ห้าม lock-in ต้อง export ครบและ exit ได้โดยไม่ขออนุญาต

## 6. ความปลอดภัยและจริยธรรม (ทำตั้งแต่ต้น ไม่ใช่ส่วนเสริม)

- เผยแพร่ threat model, bug bounty และ independent audit
- Crypto-agility และเตรียมพร้อม post-quantum
- Metadata minimization, selective disclosure เป็นค่าเริ่มต้น
- Duress PIN/ตัวตนล่อ ป้องกันการบีบบังคับ
- AI มีขอบเขตสิทธิ์ ไม่ย้ายทรัพย์สินโดยไม่มีมนุษย์ยืนยัน
- Sunset/exit plan: หากโครงการเลิก ผู้ใช้ไม่เสียทรัพย์สินหรือข้อมูล

## 7. Roadmap และเกณฑ์ตรวจรับ

| ระยะ | งานหลัก | เกณฑ์ตรวจรับ (Gate) |
|---|---|---|
| **P0: 0–6 เดือน** | เผยแพร่ Constitution + threat model; DID + KeySign; Consent Ledger; Vault ต่อคนบน OPOF | ไม่มีข้อมูลข้ามเจ้าของ (พิสูจน์แบบ OPOF); threat model ผ่านการทบทวนจากภายนอก 1 ราย |
| **P1: 6–12 เดือน** | Social recovery; ZK selective disclosure; Node 3 บทบาท; pilot กับชุมชน/SME กลุ่มเล็ก | กู้กุญแจสำเร็จตามเป้าใน pilot; ไม่มีผู้ควบคุม node เกิน 1/3 |
| **P2: 12–24 เดือน** | Marketplace + data dividend; gateway ธนาคาร/PromptPay; mesh พื้นที่ห่างไกล | ธุรกรรม offline สำเร็จ; ผ่าน audit อิสระ; ผู้ใช้ export และย้ายออกได้ครบ |
| **P3: 24 เดือนขึ้นไป** | Governance เต็มรูปแบบ; public goods fund; ขยายข้ามประเทศด้วยมาตรฐานเปิด | เปลี่ยนโปรโตคอลผ่านการลงคะแนนได้จริงอย่างน้อย 1 ครั้ง |

ตัวเลขเป้าหมาย (เช่น อัตรากู้กุญแจสำเร็จ) ต้องกำหนดร่วมกับทีมก่อนเริ่มแต่ละ Gate

## 8. ตัวชี้วัดความสำเร็จ (วัดที่ผลต่อคนธรรมดา)

- รายได้/การเข้าถึงสินเชื่อของ SME และแรงงานรายย่อยที่เพิ่มขึ้น
- จำนวนผู้ใช้ที่ควบคุม consent และกู้กุญแจได้เอง
- จำนวนเหตุข้อมูลรั่วไหลและข้อมูลข้ามเจ้าของ (เป้าหมายคือศูนย์)
- สัดส่วนผู้ใช้ในพื้นที่ห่างไกลและกลุ่มเปราะบาง

ไม่ใช้จำนวน node หรือจำนวนธุรกรรมเป็นตัวชี้วัดหลัก

## 9. ความเสี่ยงและขั้นถัดไป

| ความเสี่ยง | แนวทางลด |
|---|---|
| ข้อเสนอไม่ตรงกับสถาปัตยกรรมปัจจุบัน | ทำ gap analysis เทียบกับเอกสารจริง แล้วแตกเป็น ADR |
| ความซับซ้อนสูง (ZK, BFT, mesh) | ทำทีละชั้นตาม Gate ไม่ทำพร้อมกัน |
| กฎหมาย/ข้อบังคับ (PDPA, การเงิน) | ปรึกษาผู้เชี่ยวชาญก่อน P2 |
| ผู้ใช้กู้กุญแจไม่ได้ | ทดสอบ social recovery กับผู้ใช้จริงใน P1 |

**ขั้นถัดไป**: (1) เพิ่มเอกสารสถาปัตยกรรมปัจจุบันเข้า repo (2) ทำ gap analysis (3) แตกแต่ละหัวข้อเป็น ADR ใน `docs/adr/`
