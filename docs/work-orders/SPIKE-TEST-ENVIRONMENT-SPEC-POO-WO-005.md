# ข้อกำหนดสภาพแวดล้อมทดสอบสำหรับสไปก์ POO-WO-005 (A6, B2, B4)

- **รหัสเอกสาร: SPD-WO-004** · ร่าง 2026-09-30 · ตามคำอนุมัติ SPD-DEC-005 รอบ 2 ข้อ 6
- ที่มา: [SPD-REV-002](REVIEW-POO-WO-005-round2-2026-09-30.md) ข้อ "งานค้างก่อนรับขั้นสุดท้าย" และคำแนะนำ 1–3
- **สถานะ (ปรับปรุง 2026-10-01):** กรอกค่าแล้วตามอำนาจที่ Lead มอบ ([SPD-DEC-005](../decisions/APPROVAL-LOG-2026-09-30-FINAL-ADJUSTMENT.md) รอบ 4) · **ตัวเลขวงเงินเป็นค่าเสนอของ Claude** ไม่มีข้อมูลงบจริง Lead แก้ได้ทุกเมื่อ · **ผมไม่ได้สร้างบัญชี คีย์ หรือจัดหาเครื่องใด ๆ** ค่าที่ยังเป็น `[●]` คือสิ่งที่มีเฉพาะเจ้าของระบบรู้ (หมายเลขหน่วย KeySign, พาธ lab)

## หลักที่ใช้กับทั้งสามรายการ

1. **ไม่ใช้ข้อมูลลูกค้าจริง** ใช้ข้อมูลสังเคราะห์เท่านั้น
2. **ไม่ใช้เครื่องที่มีผู้ใช้งานอยู่** (SPD-REV-002: ผู้ทำตรวจพบ WSL2 หยุดอยู่และ Docker ไม่พร้อม จึงไม่แตะเครื่องที่ไม่ทราบเจ้าของ ซึ่งเป็นการตัดสินที่ถูกต้อง)
3. **ทดลองแล้วย้อนกลับได้:** ใช้ snapshot/ล้างทิ้งได้ทั้งเครื่อง
4. **เพดานและสวิตช์หยุด** ทุกการทดลองที่เรียกโมเดลหรือบริการที่คิดเงินต้องมีเพดานต่อรันและต่อวัน และหยุดได้ทันที
5. **ไม่เปิดการเขียนหรืออนุมัติอัตโนมัติ** ระหว่างสไปก์ (กฎถาวร SPD-DEC-005 ข้อ 6)
6. **บันทึกผลเป็นหลักฐาน** แยก ลองแล้ว / อ่านแล้ว / ไม่ทราบ ตามแบบของรายงานสไปก์

| ถ้าต้องใช้บริการเสียเงิน | บัญชีหรือคีย์ทดสอบ **แยกเฉพาะ B4** แบบ **เติมเงินล่วงหน้า (prepaid)** ที่ผู้ให้บริการเป็นผู้บังคับเพดาน ไม่ใช่เพียงสคริปต์ |
| วงเงิน (ค่าเสนอ แก้ได้) | **รวมทั้งสไปก์ 1,000 บาท · ต่อวัน 300 บาท · ต่อรัน 100 บาท** |

| ผู้ถือคีย์ | **Lead เป็นผู้สร้างและถือคีย์** ส่งให้ผู้ปฏิบัติผ่านช่องทางที่ไม่เก็บใน repo, log หรือหลักฐาน · ห้ามคีย์ที่ผูกบัญชีจริงของกิจการ |

| เกณฑ์ผ่าน | ปลุกด้วยบัญชีทดสอบได้ บันทึกว่าทำอะไร ใช้ token/ค่าใช้จ่ายเท่าใด และหยุดได้เมื่อถึงเพดาน |

### A6 — เส้นทางกุญแจ UI/CLI → อุปกรณ์ → actor assertion

| หัวข้อ | ค่า |
|---|---|
| อุปกรณ์ | ต้นแบบ KeySign หน่วยที่ผ่าน PKT-R1..R10 (13 ก.ย. 2569) **หน่วยเฉพาะสำหรับทดลอง ติดป้าย TEST-ONLY** หมายเลขหน่วย: `[●Lead ระบุ]` ห้ามใช้กับตัวตนจริงของเจ้าของ |
| ข้อจำกัดของอุปกรณ์ที่ต้องรู้ | พิสูจน์ได้เฉพาะ user presence (ต้องมีคนกดปุ่ม) · ยังไม่ล็อก secure boot/OTP · ไม่มี PIN · **ห้ามเขียน OTP/ล็อก secure boot** (ย้อนไม่ได้ รอ Lead ครบ 6 เงื่อนไข) |
| ตัวตนทดสอบ | `onevault:person:test-a6-001` (รหัสท้องถิ่นตามสัญญา C1) ห้ามออก `did:spada:*` ให้ระบบนอก SPADA · ผูกกับ SPADA ผ่าน node ทดสอบ |
| SPADA node | node ทดสอบ (dev/loopback) **ไม่ใช่ production** ไม่มีสมาชิกจริง |
| ผู้กดปุ่ม | **Lead หรือผู้ที่ Lead ระบุ `[●]`** เพราะต้องมีตัวคนกดตามคุณสมบัติของอุปกรณ์ |
| ผู้ปฏิบัติ / ผู้ตรวจ | Codex / Cowork · Lead ลงนามผลขั้นสุดท้าย |
| เกณฑ์ผ่าน | ได้ actor assertion ที่ SPADA ตรวจผ่าน (`payloadDigest` และ `nonce` ตรวจได้ ใช้ซ้ำไม่ได้) หรือบันทึกจุดที่ขาดของเส้นทางเป็นหลักฐาน |

## ห้ามทำในการทดลองนี้

- เขียน OTP/ล็อก secure boot ของ KeySign (ย้อนไม่ได้ รอ Lead ครบ 6 เงื่อนไข)
- ใช้กุญแจหรือบัญชีจริงของเจ้าของกิจการ
- เปิดการเขียน/อนุมัติอัตโนมัติของเอเจนต์ในสภาพแวดล้อมใด ๆ
- เชื่อมเครื่องทดสอบกับข้อมูลหรือเครือข่ายของลูกค้า
