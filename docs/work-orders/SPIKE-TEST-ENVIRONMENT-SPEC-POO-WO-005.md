# ข้อกำหนดสภาพแวดล้อมทดสอบสำหรับสไปก์ POO-WO-005 (A6, B2, B4)

- **รหัสเอกสาร: SPD-WO-004** · ร่าง 2026-09-30 · ตามคำอนุมัติ SPD-DEC-005 รอบ 2 ข้อ 6
- ที่มา: [SPD-REV-002](REVIEW-POO-WO-005-round2-2026-09-30.md) ข้อ "งานค้างก่อนรับขั้นสุดท้าย" และคำแนะนำ 1–3
- **สถานะ (ปรับปรุง 2026-10-01):** กรอกค่าแล้วตามอำนาจที่ Lead มอบ ([SPD-DEC-005](../decisions/APPROVAL-LOG-2026-09-30-FINAL-ADJUSTMENT.md) รอบ 4) · **ตัวเลขวงเงินเป็นค่าเสนอของ Claude** ไม่มีข้อมูลงบจริง Lead แก้ได้ทุกเมื่อ · **ผมไม่ได้สร้างบัญชี คีย์ หรือจัดหาเครื่องใด ๆ** ค่าที่ยังเป็น `[●]` คือสิ่งที่มีเฉพาะเจ้าของระบบรู้ (หมายเลขหน่วย KeySign, พาธ lab)

## หลักที่ใช้กับทั้งสามรายการ

1. **ไม่ใช้ข้อมูลลูกค้าจริง** ใช้ข้อมูลสังเคราะห์เท่านั้น
2. **ไม่ใช้เครื่องที่มีผู้ใช้งานอยู่** (SPD-REV-002: ผู้ทำตรวจพบ WSL2 หยุดอยู่และ Docker ไม่พร้อม จึงไม่แตะเครื่องที่ไม่ทราบเจ้าของ ซึ่งเป็นการตัดสินที่ถูกต้อง)
3. **ทดลองแล้วย้อนกลับได้:** ใช้ snapshot/ล้างทิ้งได้ทั้งเครื่อง
4. **เพดานและสวิตช์หยุด** ทุกการทดลองที่เรียกโมเดลหรือบริการที่คิดเงินต้องมีเพดานต่อรันและต่อวัน และหยุดได้ทันที
5. **ไม่เปิดการเขียนหรืออนุมัติอัตโนมัติ** ระหว่างสไปก์ (กฎถาวร SPD-DEC-005 ข้อ 6)
6. **บันทึกผลเป็นหลักฐาน** แยก ลองแล้ว / อ่านแล้ว / ไม่ทราบ ตามแบบของรายงานสไปก์

### A6 — เส้นทางกุญแจ UI/CLI → อุปกรณ์ → actor assertion (Lead เลือกทำทั้ง A และ B เมื่อ 2026-10-01)

**ผลตรวจหน่วยที่มีอยู่ (2026-10-01):** หน่วยต้นแบบที่เสียบอยู่ (COM7) มี token ลงทะเบียนอยู่ 1 รายการ **ผูกกับตัวตนจริงของ Lead** (uid ตรงกับ chip ID ที่วัดใน doc 345) จึง **ห้ามใช้เป็นหน่วยทดลอง A6** ไม่บันทึกตัวระบุจริง (DID, token ID, uid) ลงเอกสารใน repo นี้ ให้เรียกว่า "REAL-UNIT-1" · การยืนยันว่า COM7 คือหน่วยเดียวกันทำด้วย `pktctl info` (ไม่ต้องกดปุ่ม ไม่ลงลายเซ็น) ผลยังรอ Lead

| ส่วน | ตัวเลือก B: **A6-lite (จำลอง)** ทำได้ทันที | ตัวเลือก A: **A6-full (หน่วยที่สอง)** ทำเมื่อมีบอร์ด |
|---|---|---|
| วัตถุประสงค์ | ไล่เส้นทางซอฟต์แวร์ครบทุกขั้นเพื่อหาจุดที่ขาด (CLI → assertion → SPADA ตรวจ) | พิสูจน์ครบรวมตัวคนกดปุ่มจริง (user presence) |
| อุปกรณ์ | `--transport sim` ไม่ใช้ฮาร์ดแวร์ **ถอด REAL-UNIT-1 ออกจากเครื่องที่ทดลอง** เพื่อกันพลาด | บอร์ด RP2350 เพิ่ม 1 ตัว ติดป้าย **TEST-ONLY A6-001** จัดเตรียมตาม doc 347 P1–P7 |
| ทะเบียน | **ต้องแยก:** ตั้ง `SPADA_PKT_REGISTRY` และ `SPADA_PKT_SIM_STATE` ไปโฟลเดอร์ทดลองใหม่นอก repo เสมอ (ค่าเริ่มต้นคือ `scripts/ops/personal-key-token/registry` ซึ่งเป็นทะเบียนจริง) ตรวจ hash ของทะเบียนจริงก่อน/หลังต้องเท่ากัน | ทะเบียนทดลองแยกเช่นกัน |
| ตัวตน | DID ทดลองที่ออกบน SPADA node ทดสอบ (ไม่ใช่ DID จริง) ผูกรหัสท้องถิ่น `onevault:person:test-a6-001` ตามสัญญา C1 | เหมือนกัน |
| ผู้กดปุ่ม | **ไม่ต้องมี** (จำลอง) | **Lead หรือผู้ที่ Lead ระบุ `[●]`** ที่หน้าเครื่อง 3 จุด (enroll, selftest, sign) ตาม doc 347 |
| เกณฑ์ผ่าน | รายงานขั้นต่อขั้นว่า assertion ถูกสร้างที่ใด รูปแบบลายเซ็นตรงกันหรือไม่ SPADA ตรวจ `payloadDigest`/`nonce` อย่างไร และทดสอบ **ปฏิเสธ** ได้: ใช้ซ้ำ (`ASSERTION_REPLAYED`) หมดอายุ (`ASSERTION_EXPIRED`) payload เปลี่ยน (`CHALLENGE_MISMATCH`) · ระบุจุดที่เส้นทางขาดเป็นหลักฐาน | เหมือน A6-lite บวกหลักฐานว่าลายเซ็นแต่ละครั้งมี counter เดินและเกิดหลังตัวคนกดจริง |

| สถานะ | **พร้อมให้ Codex เริ่ม** ([SPD-HND-001](CODEX-HANDOFF-2026-10-01.md) ข้อ 4) | รอบอร์ดตัวที่สอง · ผู้กดปุ่ม `[●]` |

**ผลที่รายงานแล้ว (2026-10-01, รายงานโดย Lead, ยังไม่ได้ตรวจหลักฐาน):** ช่วง CLI → อุปกรณ์ → ลายเซ็น ทำกับ **REAL-UNIT-1 (หน่วยจริง กุญแจจริง) บนทะเบียนทดสอบแยก** แทนการจำลอง ผลผ่านครบ 4 ข้อของ `verifyAssertionFull` (ลายเซ็น, challenge, counter, ข้อความที่อนุมัติ) counter บนหน่วยเพิ่ม 1 ครั้ง ตรวจเพิ่ม 7 กรณีตามคาด รวมการปฏิเสธลายเซ็นซ้ำและข้อมูลที่ถูกแก้ และ hash chain ของทะเบียนทดสอบผ่าน · `pktctl info` ยืนยันว่าหน่วยที่ใช้คือ REAL-UNIT-1 (ค่าตรงกับทะเบียนจริง)

**ความต่างจากข้อกำหนดข้างต้น (Lead ตัดสินใจเอง):** ข้อกำหนดห้ามเซ็นกับ REAL-UNIT-1 แต่ Lead ในฐานเจ้าของเลือกทำกับหน่วยจริงเพราะได้หลักฐาน user presence ที่ `sim` ให้ไม่ได้ · **ผลนี้ติดป้าย "หน่วยจริง กุญแจจริง ทะเบียนทดสอบ บริบททดสอบ" ไม่ใช่ "SIMULATED" และไม่นับเป็นการรับรองหน่วย TEST-ONLY** · `enroll` กับหน่วยที่มีกุญแจจะลงทะเบียนกุญแจเดิม ไม่สร้างใหม่ จึงไม่ทับกุญแจ

**ยังไม่ทดสอบ:** ช่วง OneVault → actor assertion ที่ SPADA node ทดสอบยอมรับ · หลักฐานต้นฉบับเก็บนอก repo นี้ **ห้ามนำ token ID, board uid, public key หรือ DID เจ้าของลง repo นี้** (repo เป็น public) ให้ส่งหลักฐานขึ้น `onemanos-setbox` (private) เท่านั้น

## ห้ามทำในการทดลองนี้

- เขียน OTP/ล็อก secure boot ของ KeySign (ย้อนไม่ได้ รอ Lead ครบ 6 เงื่อนไข)
- ใช้กุญแจหรือบัญชีจริงของเจ้าของกิจการ
- เปิดการเขียน/อนุมัติอัตโนมัติของเอเจนต์ในสภาพแวดล้อมใด ๆ
- เชื่อมเครื่องทดสอบกับข้อมูลหรือเครือข่ายของลูกค้า
