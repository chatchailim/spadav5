## คำถามที่ขอให้ตอบ (ขอบเขตเสนอ ผู้ตรวจเพิ่ม/ตัดได้)

1. ลำดับตรวจฝั่ง SPADA (ADR §2 ข้อ 5) ครบและ fail-closed หรือไม่ มีลำดับใดที่ทำให้เกิด oracle หรือเขียนสถานะก่อนตรวจครบ
2. `contextHash = SHA-256(ไบต์ assertion)` ผูกครบทุกฟิลด์จริงหรือไม่ ตัวคั่น `\\n` ใน `encodeSPADAActorAssertion` กำกวมได้หรือไม่เมื่อค่าฟิลด์มี newline และต้องห้ามหรือ escape ที่จุดใด
3. counter + nonce ต้อง atomic: สองคำขอด้วย counter เดียวกันพร้อมกัน, ล้มหลังตรวจก่อนบันทึก, หลายโหนด (ถ้ามี) นโยบายใดปลอดภัย
4. เพิกถอนทันทีและไม่ cache · อุปกรณ์ที่ถูก FACTORY_RESET (counter ย้อน) ต้องถือเป็นอุปกรณ์ใหม่อย่างไร
5. `challenge` ที่ host สุ่มเอง (Lead ตัดสิน Q1) ทำให้ replay ภายในช่วงอายุเปิดช่องได้เท่าไร เทียบกับให้ SPADA ออก challenge และผลของนาฬิกาเลื่อน
6. กุญแจ KeySign เข้ากับ `signingPublicKey` ใน device record ในรูปแบบและอัลกอริทึมหรือไม่ (ADR ระบุให้ตรวจก่อนรับ)
7. algorithm ใหม่ไม่กระทบ algorithm เดิม · `deviceAssurance` ไม่เกิน `NATIVE`
8. ความเสี่ยงอื่นที่ผู้ตรวจเห็น (ขอให้ระบุระดับความรุนแรงและเงื่อนไขที่ทำให้เกิด)
