## เงื่อนไขชดเชยความเสี่ยงรหัส root (ต้องทำก่อนอย่างอื่น)

1. **ตรวจ ACL ของ tailnet** ว่า `node-b` ถูกจำกัดสิทธิ์: ผู้ดูแลเข้า `node-b` ได้เฉพาะพอร์ต 22 และ `node-b` เชื่อมไปเครื่องอื่นใน tailnet ไม่ได้ ถ้ายังไม่ได้ตั้งให้รายงาน Lead ตั้งในหน้า admin (agent ไม่แก้ ACL เอง) ห้ามถือว่าผ่านโดยไม่ตรวจ
2. **สร้างผู้ดูแล `<ADMIN_USER>` พร้อม SSH key และ sudo** ผ่าน tailnet แล้วทดสอบเข้าด้วย key ก่อน
3. **ปิด SSH ด้วยรหัสผ่านและปิด root login ด้วยรหัสผ่านที่ขั้น S03 (gate G1) เป็นขั้นแรกหลังข้อ 2** เพื่อให้รหัส root ที่รั่วใช้ผ่าน SSH ไม่ได้อีก (ต้องรอ Lead ตอบ `อนุมัติ G1`)
4. **ห้ามเก็บข้อมูลจริงของลูกค้า กุญแจ หรือความลับของโครงการบน Node B** ในช่วงนี้ ใช้ข้อมูลสังเคราะห์เท่านั้น
5. ถ้าพบร่องรอยผู้อื่นเข้าเครื่อง (ผู้ใช้แปลก โปรเซสแปลก login ที่ไม่ใช่ของเรา) **หยุดและรายงานทันที**

## งานที่ทำได้ตอนนี้ (ก่อน Node A พร้อม)

- ติดตั้งอัปเดตค้างและรีบูต (รายการรอรีบูต) แล้วยืนยันว่า Tailscale กลับมา
- เช็กสเปก (อ่านอย่างเดียว) และยืนยัน `systemd-detect-virt` ไม่ใช่ `openvz`/`lxc` · ตรวจรองรับ Docker
- เตรียมเครื่องตามขั้นเตรียม Node B ของ WO-N ที่ไม่ขึ้นกับ Node A
- **ห้ามทำ:** เปิด ufw ก่อน Lead ตอบ G3 · ปิดพอร์ต 22 สาธารณะ (G4 เป็นงานของคน) · ออกหรือแตะใบรับรอง federation และ CA (R3) · `up` ครั้งแรกหรือออกใบรับรองจริง (G5) จนกว่า Lead อนุมัติ · แก้ ACL tailnet
