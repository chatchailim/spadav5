## 2. สิ่งที่ A1 บอก และผลต่อการออกแบบ F1

| ข้อค้นพบ | ผลต่อแผน |
|---|---|
| **"GET" ไม่เท่ากับอ่านอย่างเดียว:** `GET /executive/overview` และ `GET /approvals/queue` เขียน `audit_events` สำเร็จ และ `GET /cash/payment-methods` ที่ถูกปฏิเสธก็เขียน audit 1 statement | policy "เอเจนต์อ่านอย่างเดียว" ต้องนิยามว่า **อนุญาตการเขียน audit** (และต้องมีทางตรวจ) ห้ามใช้เมธอด HTTP เป็นเกณฑ์ |
| **ไม่มี route ใดถูกพิสูจน์ว่า reversible** (`reversibility` ทั้ง 171 = "NOT PROVEN") | **ยังใช้เพดานอิสระของ D2.1 กับ route ธุรกิจไม่ได้** ต้องมี compensation contract ต่อ route ก่อน (ตรงกับ SPD-DEC-005 ข้อ 6 ที่ยังไม่เปิดเขียนอัตโนมัติ) |
| 20 จาก 171 route มี human-name gate (`humanNameGate=true`) | ตรงกับที่ ADR 0016 §4 เตือน gate นี้เป็นการตรวจรูปแบบชื่อ ไม่ใช่การพิสูจน์ตัวตน จึงไม่นับเป็นหลักฐานของ SPADA |
| `POST /admin/users/:subjectId/unlock` เขียน `local_credentials` และ audit แม้ใช้ ID ที่ไม่มีอยู่ | เป็น route ระดับสิทธิ์สูง ต้องอยู่ใน **รายการห้าม** ของ Responsibility ใด ๆ โดยปริยาย |
| static: ทุก route อาจเขียนอย่างน้อย `audit_events` (44 ชื่อตารางที่ route อาจเขียน, สหภาพแบบอนุรักษ์) | ใช้เป็น **ขอบเขตบน** ได้ ไม่ใช่ข้อมูลว่าเขียนจริง |

**ข้อสรุปเชิงออกแบบ:** allowlist ของ Responsibility ควรระบุ **route/tool ที่อนุญาตทีละรายการ** (default deny) พร้อมชนิด effect ที่ยอมรับได้ ไม่ใช่ตามบทบาท (architect/secretary/builder/operator) หรือเมธอด HTTP ซึ่งตรงกับร่าง SPD-ADR-D04 กติกาข้อ 4

## 3. ข้อจำกัดของหลักฐาน (ที่ผู้ทำระบุและผมเห็นด้วย)

- ผลลองจริงใช้ **body ว่างและ resource ID ที่ไม่มีอยู่** จึง 117 จาก 171 route ล้มก่อนถึงเส้นทางเขียนจริง ผลจึง **ไม่ครอบคลุมพฤติกรรมเขียนของ route ที่รับ input ถูกต้อง**
- เรียก **dispatcher โดยตรง** ด้วย development session ไม่ใช่ขอบเขต MCP/HTTP และไม่ใช่การรับรอง authentication
- การวิเคราะห์ static ไม่ใช่ type checker สมบูรณ์ มีจุด dynamic ที่ผู้ทำ override หลังอ่านซอร์ส (`crm.js:579–580`)
- ผมทำซ้ำผลลองและตรวจ route list กับ inventory เอง แต่ **ไม่ได้ตรวจเส้นทาง call graph รายตัว** ทั้ง 171 route และไม่ได้ตรวจ 44 ชื่อตารางทีละตัว
