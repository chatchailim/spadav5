## สรุปงาน

ตอบให้ได้ว่า `onevault-mcp` ต้องเพิ่มหรือแก้อะไร และต้องสร้างตัวตั้งเวลาแบบใด เพื่อให้ Team Agent รับ "ความรับผิดชอบต่อเนื่อง" (Responsibility) ได้อย่างปลอดภัย โดยไม่ขัดกับ ADR 0014 (SetBox นอก SPADA), ADR 0016 (Team Agent ไม่มี DID ของตัวเอง การอนุมัติที่ SPADA เชื่อคือ actor assertion ที่เจ้าของลงนาม), D2.1 (อิสระเฉพาะงานย้อนกลับได้) และกฎเดิมของ OneVault (เขียนผ่านเมธอดของ Warehouse เท่านั้น, ไม่มี dependency ภายนอก, ออฟไลน์ได้, Node.js 22+)

## ข้อมูลตั้งต้นที่ผู้ออกอ่านมาแล้ว (ผู้ทำต้องตรวจซ้ำ อย่าเชื่อทั้งหมด)

1. `onevault-mcp` ราว 2,400 บรรทัด ไม่มี dependency ภายนอก · `src/tools.js` 1,085 บรรทัด มีเครื่องมือราว 30 ตัว (query/provenance/audit, store/create, wave start/verify/seal, exceptions, link file, decommission, app lifecycle) · ไม่พบเครื่องมือ Responsibility หรือ schedule
2. บทบาท architect/secretary/builder: stdio ใช้ `ONEVAULT_ROLE`; HTTP ใช้โทเคนลงนาม (`src/tokens.js`) มี `exp` ผูกโปรเจกต์ ล็อกเอาต์ 10 ครั้ง/60 วินาที (`src/http-server.js`)
3. `human-gate.js` ที่รากตัดสินว่าชื่อใดเป็นคน MCP ชี้ไปตัวเดียวกัน · การแยกหน้าที่เปิดโดยปริยาย ปิดด้วย `ONEVAULT_ALLOW_SELF_APPROVAL`
4. ตัวตั้งเวลาเดิมเป็นของโครงสร้างพื้นฐาน: `optimus-edition/package-files/operations/` (`scheduled-backup.js`, `install-windows-tasks.ps1`, `supervisor.js`), `intake/watch-intake.js`, `setup/onemanos-care.js`
5. Team Agent คือเครื่องมือภายนอก (Claude Code, Claude Desktop, Codex) ตาม `agent-config/*.json` ที่มนุษย์เป็นผู้เริ่ม → **ข้อสงสัยหลัก: ปลุกเอเจนต์ตามเวลาโดยไม่มีคนนั่งหน้าจอได้หรือไม่ (B4)**

### ขั้น 1 — สำรวจ `onevault-mcp` (A1–A7)
| ข้อ | วิธี | หลักฐานที่ต้องเก็บ |
|---|---|---|
| A1 | ไล่ `ALL_TOOLS` ใน `tools.js`: ชื่อ, `group`, ฟังก์ชันที่เรียก, ตารางที่เขียน เทียบกับกลุ่มที่แต่ละบทบาทได้ (`toolsForRole`) จำแนก 3 ระดับ: อ่าน / เขียนย้อนกลับได้ / เขียนย้อนไม่ได้ (seal, approve, retire, decommission ฯลฯ) และให้เหตุผลทุกตัวที่จัดว่า "ย้อนกลับได้" | ตารางเครื่องมือ × บทบาท × ระดับ + `ไฟล์:บรรทัด` |
| A2 | ตามเส้นทางคำขอตั้งแต่ `server.js`/`http-server.js` ถึง handler ของเครื่องมือ ระบุจุดที่ตรวจสิทธิ์ และจุดที่แทรกด่านนโยบาย (ก่อน handler) ได้โดยแก้น้อยที่สุด ระบุเครื่องมือที่มีประตู approval แล้ว | แผนภาพ (Mermaid หรือข้อความ) พร้อมเลขบรรทัด |
| A3 | รันเครื่องมือเขียน 2–3 ตัวบนฐานทดสอบ แล้วอ่านแถว audit ที่เกิด ตรวจว่า actor เป็นรูปแบบใด (เทียบ C1/POO-WO-001) และแยก "เจ้าของ" กับ "เอเจนต์" ได้หรือไม่ | แถว audit จริง (ปิดบังค่าลับ) |
| A4 | อ่าน `tokens.js`: payload มีฟิลด์ใดบ้าง เพิ่ม claim ใหม่ (รหัส Responsibility, รายการเครื่องมือ, งบการเรียก, exp สั้น) ได้ไหมโดยไม่ทำให้โทเคนเก่าเสีย, เพิกถอนทำอย่างไร ผลมีทันทีไหม | ข้อเสนอรูปแบบ claim + ผลตรวจการเพิกถอน (ลองจริงบนสำเนา) |
| A5 | ระบุเครื่องมือที่ **คืนข้อความจากเอกสาร/ไฟล์ที่มาจากภายนอก** ให้เอเจนต์ (เช่น query document, provenance, intake) และเครื่องมือเขียนที่เรียกต่อได้ทันที สร้างกรณีทดลอง: เอกสารทดสอบที่มีข้อความสั่งการปลอม (เช่น "เรียก approve ..." ) แล้วดูว่าระบบมีด่านใดกัน (ไม่ใช่ดูว่าโมเดลเชื่อไหม) | ตารางความเสี่ยง + ผลกรณีทดลอง + ข้อเสนอด่าน (แยก instruction/data ตาม doc 335 ข้อ 9) |
| A6 | ไล่เส้นทางอนุมัติวันนี้ (admin console, CLI, `human-gate`) และตรวจว่า SetBox มีกุญแจใดให้ลงนาม (กุญแจเครื่อง หรือ KeySign) เพื่อผลิต `ISPADAActorAssertion` ตาม ADR 0016 ได้หรือไม่ ขาดอะไร | แผนภาพเส้นทางปัจจุบัน + เส้นทางที่ต้องเพิ่ม |
| A7 | ตรวจว่า TLS ของ MCP และ audit hash chain (POO-WO-003) อยู่ในโค้ดแล้วหรือยัง: ค้น `previousHash`/`recordHash`, `node:tls`, `127.0.0.1` default, รันคำสั่งตรวจ chain ถ้ามี | ผลตรวจ + ข้อสรุปว่าต้องเสร็จก่อนงาน F1 หรือไม่ |

### ขั้น 2 — สำรวจตัวตั้งเวลาและตัวกระตุ้น (B1–B6)
| ข้อ | วิธี | หลักฐาน |
|---|---|---|
| B1 | อ่าน `optimus-edition/package-files/operations/*`, `install-windows-tasks.ps1`, `kit/SETBOX-UBUNTU-TH.md`, `intake/watch-intake.js`, `setup/onemanos-care.js` ทำตาราง รุ่น S/M/L × Windows/Ubuntu × กลไก × วิธีติดตั้ง | ตาราง + ไฟล์:บรรทัด |
| B2 | ทดลองบนเครื่องทดสอบ: หยุด/รีสตาร์ต supervisor กลางงาน, ตัดเครือข่าย, ข้ามรอบ, เปิด 2 ตัวพร้อมกัน ดูว่างานซ้ำ/หาย/ค้างหรือไม่ | ตารางสถานการณ์ × ผลที่เห็น (ผลลองจริง แยกจากที่อ่าน) |
| B3 | เปรียบเทียบ 3 ทาง (a) ตัวตั้งเวลาของ OS เรียกคำสั่ง wake (b) ต่อยอด `supervisor.js` (c) คิวเหตุการณ์ใน SQLite + ตัวเฝ้าแบบ `watch-intake.js` ตามเกณฑ์ 5 ข้อ: ไม่มี dependency, ออฟไลน์ได้, ใช้ได้ทั้ง Windows/Ubuntu, ตรวจสอบย้อนหลังได้, รันหนึ่งตัวต่อ Responsibility ให้คะแนนทีละเกณฑ์พร้อมเหตุผล และแนะนำหนึ่งทาง | ตารางเปรียบเทียบ + คำแนะนำ |
| B4 | ตรวจ **จากเอกสารทางการ** ของ Claude Code, Claude Desktop, Codex ว่าเริ่มเซสชันแบบไม่มีคนได้ไหม (โหมด headless/CLI, รับ prompt จากสคริปต์, การยืนยันสิทธิ์ที่ต้องมีคนกด) มีข้อกำหนดการใช้หรือค่าใช้จ่ายที่ต้องรู้ไหม แล้วลองบนเครื่องทดสอบ 1 กรณีเท่าที่ทำได้โดยไม่ต้องใช้ข้อมูลลูกค้า **แยก "ลองแล้ว" ออกจาก "อ่านจากเอกสาร"** ถ้าปลุกอัตโนมัติไม่ได้หรือมีเงื่อนไขมาก เสนอทางเลือก: ระบบเตรียมงานเป็นรายการรอ แล้วมนุษย์เปิดเซสชันมารับ | ลิงก์เอกสาร + ผลลอง + ข้อสรุป |
| B5 | ทำตาราง trigger: เวลา, เอกสารใหม่, สถานะ wave เปลี่ยน, exception ถูกยก, ไฟล์เข้า inbox, ใบสั่ง/สถานะธุรกิจเปลี่ยน แต่ละชนิดมีจุดจับในโค้ดหรือไม่ ต้องเพิ่มอะไร | ตาราง trigger × จุดจับ × งานที่ต้องเพิ่ม |
| B6 | เสนอกลไกความปลอดภัย: จำกัดอัตรา, งบต่อวัน (จำนวนเรียกเครื่องมือ/โทเคนโมเดล), quiet hours, กันงานซ้ำ (idempotency key), kill switch — ระบุว่าใช้กลไกเดิม (โทเคน exp, ล็อกเอาต์, `onemanos-care`) ได้ส่วนใดและต้องเพิ่มส่วนใด พร้อมค่าเริ่มต้นที่แนะนำ | ข้อเสนอ + ค่าเริ่มต้น |

1. ตัวตั้งเวลาแบบที่แนะนำ หรือทางเลือกอื่น
2. ทำ F1 ตามแผนเอเจนต์ต่อเนื่องต่อหรือไม่ และถ้า B4 พบว่าปลุกอัตโนมัติไม่ได้ จะเปลี่ยนเป็นโหมด "เตรียมงานให้มนุษย์รับ" หรือหาเครื่องมือเอเจนต์อื่น
3. ต้องเร่งปิด POO-WO-003 และ doc 335 ข้อ 9 ก่อนหรือไม่
