- ห้ามใส่ IP พาธเครื่อง รหัสผ่าน กุญแจ หรืออีเมลจริงใน repo สาธารณะ ค่าทุกอย่างด้านล่างเป็นตัวแทน

## ขอบเขต (ตามเอกสารของ Codex)
สำรองต่อ node: `infra/docker/.node-keys/node.json` · `infra/docker/.certs/federation/` (เฉพาะไฟล์ปกติ) · `infra/docker/.certs/oidc/signing-key.json` · `infra/docker/env/node.env` · **ไม่รวม** `.certs/ca.key`, `server.*`, `client.*` และไฟล์ dev อื่น · ไม่ย้ายหรือลบต้นฉบับ · ไม่หยุดบริการ · ไม่ใช้ G6 · ไม่ต้องมีดิสก์สำรอง

## ข้อสังเกตก่อนเริ่ม (ของ Claude ไม่ใช่คำตัดสิน)
1. **ต้องมีอนุมัติแยกเป็นข้อยกเว้นของ R2:** การคัดลอกกุญแจ node ออกนอกเครื่องขัด R2 (ห้าม `cp` ไฟล์ความลับไปที่อื่น) ข้อความของ Lead ที่ว่า "ตัดสินใจแล้ว" ไม่ระบุข้อยกเว้นนี้ชัดเจน ขอให้ Lead พิมพ์เฉพาะเจาะจง เช่น "อนุมัติ S20-A: สำรองไฟล์ในขอบเขตข้างต้นแบบเข้ารหัสออกนอก node"
2. **ใช้การเข้ารหัสด้วยกุญแจสาธารณะ ไม่ใช้รหัสผ่าน:** ให้ Lead สร้างคู่กุญแจ (เช่นด้วยเครื่องมือ `age`) กุญแจส่วนตัวอยู่ออฟไลน์กับ Lead เท่านั้น เครื่อง controller และ agent ถือแค่กุญแจสาธารณะ จึงไม่มีรหัสผ่านใน command line, log หรือแชต และ agent ถอดรหัสไฟล์เองไม่ได้
3. **กุญแจส่วนตัวหาย = ถอดรหัสไม่ได้ตลอดไป** ต้องมีสำเนาของกุญแจส่วนตัวอย่างน้อยสองที่ (คนละที่กัน) เก็บแยกจากไฟล์สำรอง
4. **ไม่ให้มี plaintext บนดิสก์:** ส่งข้อมูลจาก node ผ่าน SSH เข้า pipe เข้ารหัสบน controller โดยตรง (plaintext อยู่ในหน่วยความจำเท่านั้น) บน Windows ต้องใช้ `cmd /c` สำหรับ pipe แบบไบนารี เพราะ PowerShell 5.1 อาจทำให้ข้อมูลไบนารีเสียหาย
5. **เก็บ ciphertext อย่างน้อยสองสำเนา** (เช่นบน controller นอก repo/โฟลเดอร์ซิงก์ และอีกที่หนึ่งที่ Lead เลือก) เพราะ controller เครื่องเดียวเป็นจุดล้มเหลวจุดเดียว
6. ห้ามนำไปแทน restore drill ของทั้งระบบ (S20-B) การตรวจในขั้นนี้พิสูจน์แค่ว่าถอดรหัสได้และไฟล์ครบ

## P0 Lead เตรียม (ครั้งเดียว)
1. ติดตั้ง `age` บน controller จากหน้าปล่อยเวอร์ชันทางการ ตรวจ checksum/ลายเซ็นก่อนใช้ (Codex ระบุว่าจะตรวจที่มา)
2. สร้างคู่กุญแจ **บน USB หรือที่ออฟไลน์** ไม่ใช่ในโฟลเดอร์ของ agent: `age-keygen -o <USB>\spada-backup.key` จะแสดงกุญแจสาธารณะ (ขึ้นต้น `age1...`) ส่งเฉพาะกุญแจสาธารณะให้ Codex
3. สำรองไฟล์กุญแจส่วนตัวอีกชุดไปไว้คนละที่ และถอด USB เก็บ
4. ยืนยันสถานะเข้ารหัสของไดรฟ์ที่จะใช้ (เช่นตรวจ BitLocker) ก่อนเก็บ ciphertext ที่นั่น Codex ระบุว่ายังไม่ยืนยันสถานะไดรฟ์ E

## P1 Codex ตรวจก่อนลงมือ (อ่านอย่างเดียว)
- ยืนยันรายการไฟล์และขนาดตรงกับที่ตรวจไว้ (metadata เท่านั้น) และ `tar` อ่านได้ด้วยบัญชี `onemanadmin` โดยไม่ต้องใช้ `sudo` (R14) ถ้าอ่านไม่ได้ **หยุดแจ้ง Lead** ห้ามใช้ `sudo` เอง
- เก็บ `sha256sum` ของแต่ละไฟล์ในขอบเขตจาก node ไว้เป็น manifest (ค่า hash ไม่เผยเนื้อหา)

## P2 สำรองต่อ node (ตัวอย่างของ Node A เปลี่ยนชื่อ node ให้ตรง)
ตัวแปร: `PUB` = กุญแจสาธารณะ `age1...` ของ Lead, `OUT` = โฟลเดอร์ปลายทางบน controller
```cmd
cmd /c "ssh -n -o BatchMode=yes onemanadmin@node-a "umask 077; tar -C ~/spada-monorepo/infra/docker -cf - .node-keys/node.json .certs/federation .certs/oidc/signing-key.json env/node.env" | age -r %PUB% -o %OUT%\th-bkk-001-s20a-<วันที่>.tar.age"
```
ทำเช่นเดียวกันกับ Node B (`th-bkk-002`) ลงไฟล์แยก ไม่รวมสอง node ในไฟล์เดียว ห้ามแสดงผลลัพธ์ของ pipe ลงจอ

> **แก้ไขหลังรายงานของ Codex (2 ต.ค. 2026):** ตัวอย่าง `cmd /c "ssh ... | age ..."` ด้านบน **ตรวจสถานะการออกของ `ssh`/`tar` ไม่ได้** (pipe ใน cmd คืนเฉพาะสถานะของ `age`) ถ้า `tar` ล้มเหลว อาจได้ไฟล์เข้ารหัสที่ว่างหรือขาดแต่ดูเหมือนสำเร็จ ให้ถือตัวอย่างนี้เป็นเพียงภาพรวม ตอนลงมือต้องใช้ pipeline แบบ binary-safe (เช่นสคริปต์ที่เปิด `ssh` และ `age` เป็น subprocess แยกกัน) ตรวจ return code ของทั้งสองและต้องไม่นับไฟล์ว่าง/ขาดเป็น PASS · ระบุรายการไฟล์ปกติแบบ allowlist ตรวจ symlink และตรวจว่ารายการไม่เปลี่ยนก่อน/หลัง ไม่กวาดทั้งโฟลเดอร์ `federation/` · ตรวจจำนวนไฟล์และขนาดของ ciphertext ว่าสมเหตุสมผลก่อนไป P3

## P3 ตรวจความครบ (Lead ถือกุญแจส่วนตัว ถอดรหัสในหน่วยความจำ)
1. รายชื่อไฟล์ในไฟล์สำรอง ไม่เขียนลงดิสก์: `age -d -i <USB>\spada-backup.key <ไฟล์>.age | tar -tf -`
2. hash ต่อไฟล์เทียบกับ manifest ใน P1 โดยไม่เขียน plaintext: ส่ง `tar -xOf - <พาธ>` เข้า Node แล้วคำนวณ SHA-256 จาก stdin (ตัวอย่าง `node -e` ที่อ่าน stdin) จนครบทุกไฟล์
3. ผลที่ผ่าน: จำนวนไฟล์ตรง รายการพาธตรง hash ทุกไฟล์ตรง

## P4 บันทึกและเก็บ
- บันทึก (ภายในเท่านั้น): hash ของ ciphertext, จำนวนไฟล์, วิธีเข้ารหัส, ที่เก็บแต่ละสำเนา, ผลตรวจ P3, ข้อจำกัด · ไม่ใส่เนื้อหาหรือกุญแจ
- คัดลอก ciphertext ไปที่เก็บสำเนาที่สอง แล้วตรวจ hash ตรงกัน
- ถอด USB ที่มีกุญแจส่วนตัวออกและเก็บ

## ทางเลือกถ้า pipe บน Windows ใช้ไม่ได้
ติดตั้ง `age` บน node (ต้อง `sudo apt-get install` ซึ่งอยู่นอกใบงาน ต้องให้ Lead อนุมัติแยก) เข้ารหัสบน node ด้วยกุญแจสาธารณะ เขียน ciphertext ไว้ชั่วคราว คัดลอกมาที่ controller ตรวจ hash แล้วลบไฟล์ ciphertext บน node เพราะเข้ารหัสแล้วไม่ใช่ความลับ แต่ยังต้องไม่ทิ้งไว้ ไม่แนะนำเป็นทางหลัก
