# ทะเบียนฮาร์ดแวร์ SetBox แบบเดี่ยว (Track S) — แม่แบบ v0.1

- **รหัสเอกสาร: SPD-PRC-004**

> สถานะ: **แม่แบบเปล่า (ร่าง)** · วันที่ 2026-09-29 · ตามทิศทางของ Lead: แยกจากทะเบียนฝั่ง SPADA (doc 344) และรวมเครื่องรายตัวเข้าทะเบียนฝั่ง SPADA ได้เมื่อเจ้าของเครื่องลงทะเบียนเป็นสมาชิก SPADA และผ่านเงื่อนไข
> ที่ตั้งจริงที่เสนอ: repo `onemanos-setbox` (ฝั่ง OneManOS ตาม ADR 0014) · ผมมีสิทธิ์อ่านอย่างเดียวใน repo นั้น จึงเก็บแม่แบบไว้ที่นี่ให้คัดลอกไปใช้
> อ้างอิง: [ร่าง ADR ขอบเขต ADR 0020](../decisions/ADR-DRAFT-hardware-qualification-scope.md), doc 344 §3 (ขั้นตอนวัด), [มาตรฐานจัดซื้อ](SETBOX-PROCUREMENT-STANDARD.md)

## 0. อ่านก่อนใช้

- **เจ้าของทะเบียน/ผู้ลงนาม**: ฉัตรชัย หลิมประเสริฐศิริ (ชั่วคราว) · ผู้สำรอง: ยังไม่กำหนด · ผู้ตรวจ evidence คนที่สอง: ยังไม่กำหนด
- **เกณฑ์ฐาน HB** = ระดับ NATIVE-ELIGIBLE ของ ADR 0020: TPM 2.0 บนฮาร์ดแวร์จริง (**vTPM ปฏิเสธเสมอ**), Secure Boot เปิดและอยู่ใน user mode, PCR bank SHA-256 ครบ, อ่าน event log ได้, ปิดช่องดีบัก (DCI/JTAG) ถาวรได้ (รอ Lead ยืนยันการใช้เกณฑ์นี้ตามร่าง ADR)
- **ทะเบียนนี้ไม่ใช่การรับรองจาก SPADA** และห้ามอ้างว่าเป็น `deviceAssurance` ใดๆ
- **append-only**: ถอนรุ่น/เปลี่ยนสถานะ = เพิ่มรายการใหม่ที่อ้างรายการเดิม ห้ามลบแถว
- **BIOS/TPM firmware เป็นส่วนหนึ่งของรายการ** เปลี่ยนแล้วต้องวัดและลงรายการใหม่
- **วัดจากเครื่องจริงเท่านั้น** ห้ามลงรายการจากเอกสารผู้ขายหรือคำบอกเล่า

## 1. ระดับที่บันทึก

| ระดับ | เงื่อนไข | ผลต่อการขาย/ติดตั้ง Track S |
|---|---|---|
| ❌ REJECTED | ไม่ผ่านเกณฑ์ HB ข้อใดข้อหนึ่ง (รวมถึง vTPM) | ติดตั้งไม่ได้ |
| 🟡 HB-PASS | ผ่านเกณฑ์ HB ทุกข้อ ไม่มี EK certificate หรือ chain ตรวจไม่ได้ | ติดตั้ง Track S ได้ · เชื่อม SPADA ได้ที่ระดับ `NATIVE` ตามเงื่อนไขการรวมทะเบียน |
| 🟢 HB-PASS+EK | ผ่าน HB และอ่าน EK certificate ได้ พร้อม chain ถึง root ที่ยืนยัน (ตามที่ allowlist ของ SPADA ยอมรับ) | เหมือนข้างบน และเปิดทาง APPLIANCE-CANDIDATE เมื่อรวมทะเบียน (ปัจจุบัน `APPLIANCE` ยังถูกบล็อก) |
