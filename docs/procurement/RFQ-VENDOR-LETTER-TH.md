# แม่แบบจดหมายถึงผู้ขาย: คำถามบังคับก่อนรับใบเสนอราคา (ร่าง)

- **รหัสเอกสาร: SPD-PRC-002**

> **Lead อนุมัติให้ใช้ (2026-09-29)** ยังไม่ได้ส่ง ผู้จัดซื้อต้องกรอกชื่อ/วันที่/กำหนดตอบก่อนส่ง · ใช้คู่กับ [SETBOX-PROCUREMENT-STANDARD](SETBOX-PROCUREMENT-STANDARD.md) ข้อ D1 · อิงคำถามใน doc 344 §5 และ ADR 0020 §4
> **ก่อนส่ง**: ตรวจข้อความ ใส่ชื่อ/วันที่/กำหนดตอบ และอย่าเปิดเผยรายละเอียดสถาปัตยกรรมภายในเกินจำเป็น (จดหมายนี้ไม่มีข้อมูลลับ)
> **ห้ามรับมอบใบเสนอราคาก่อนได้คำตอบข้อ 1–8 ครบเป็นลายลักษณ์อักษร**

---

**เรื่อง** ขอคำยืนยันคุณสมบัติด้านความปลอดภัยของเครื่องคอมพิวเตอร์ ประกอบการพิจารณาใบเสนอราคา
**เรียน** [ชื่อผู้ขาย / ผู้แทนฝ่ายขาย]
**จาก** [ชื่อบริษัท/ผู้จัดซื้อ] · **วันที่** [วันที่] · **อ้างอิง RFQ** [เลขที่]

ตามที่บริษัทฯ ขอใบเสนอราคาเครื่อง [รุ่น/SKU ที่ระบุใน RFQ] จำนวน [X] เครื่อง ก่อนพิจารณาใบเสนอราคาและสั่งซื้อ บริษัทฯ ขอให้ท่านตอบคำถามต่อไปนี้ **เป็นลายลักษณ์อักษร (อีเมลหรือหนังสือ)** ภายในวันที่ [กำหนด] คำตอบจะถูกเก็บเป็นหลักฐานประกอบการจัดซื้อ และบริษัทฯ จะตรวจวัดคุณสมบัติจากเครื่องตัวอย่างก่อนสั่งซื้อจำนวนมาก

## ก. คำถามเกี่ยวกับ TPM และการบูตที่ปลอดภัย

| ข้อ | คำถาม | คำตอบของผู้ขาย |
|---:|---|---|
| 1 | เครื่องรุ่น/SKU นี้ใช้ TPM 2.0 แบบใด: **discrete TPM (ชิปแยก)** หรือ **firmware TPM (fTPM/PTT ใน CPU)** หรืออื่นๆ ระบุให้ชัด และยืนยันว่าเป็น TPM บนฮาร์ดแวร์จริง ไม่ใช่ TPM เสมือน | |
| 2 | ผู้ผลิตและรุ่นของ TPM รวมถึงเวอร์ชัน firmware ของ TPM ที่จัดส่ง | |
| 3 | ถ้าเป็น fTPM: TPM มี **Endorsement Key (EK) certificate** เขียนไว้ใน NV index จากโรงงานหรือไม่ และ certificate chain ไปถึง root certificate ของผู้ผลิตรายใด | |
| 4 | ขอไฟล์ **root/intermediate certificate chain ของ EK** สำหรับรุ่นนี้ (แนบมาพร้อมคำตอบ) | |
| 5 | เวอร์ชัน **BIOS/UEFI** ที่จัดส่ง และมีการเปลี่ยนสถานะหรือพฤติกรรมของ TPM ระหว่างเวอร์ชัน BIOS หรือไม่ | |
| 6 | **Secure Boot** เปิดใช้ได้และตั้งเป็น user mode (เพิ่ม/เปลี่ยน key ของผู้ใช้เอง) ได้หรือไม่ | |
| 7 | **ช่องดีบัก (DCI/JTAG หรือเทียบเท่า)** ปิดถาวรได้หรือไม่ และทำอย่างไร | |
| 8 | หากสั่งจำนวนมาก ท่านรับประกันเป็นลายลักษณ์อักษรหรือไม่ว่า **ทุกเครื่องในล็อตใช้รุ่น, BIOS, TPM ชนิดและ firmware เดียวกัน** และจะแจ้งล่วงหน้าเป็นลายลักษณ์อักษรก่อนเปลี่ยนชิ้นส่วนหรือ firmware | |

## ข. คำถามเชิงพาณิชย์และห่วงโซ่อุปทาน

| ข้อ | คำถาม | คำตอบของผู้ขาย |
|---:|---|---|
| 9 | สินค้าเป็นของใหม่ไม่ผ่านการใช้งาน (ไม่ใช่ refurbished) หรือไม่ และนำเข้าผ่านช่องทางใด (ผู้แทนจำหน่ายที่ได้รับอนุญาตจากผู้ผลิตหรือไม่) | |
| 10 | เครื่องจัดส่งพร้อมซอฟต์แวร์หรือบัญชีที่ผู้ขายติดตั้งไว้หรือไม่ (บริษัทฯ จะล้างและติดตั้งระบบใหม่ทั้งเครื่องก่อนใช้) | |
| 11 | ระยะเวลารับประกัน เงื่อนไขซ่อม/เปลี่ยน และแนวทางกรณีต้องเปลี่ยนเมนบอร์ดหรือชิป TPM (การเปลี่ยนดังกล่าวทำให้ต้องรับรองเครื่องใหม่) | |
| 12 | ราคา เงื่อนไขชำระเงิน ระยะเวลาส่งมอบ และอายุของใบเสนอราคา | |
| 13 | ขอตัวอย่างสำหรับตรวจวัดจำนวน 1–2 เครื่องก่อนสั่งล็อต พร้อมเงื่อนไข (ซื้อ/ยืมทดสอบ/คืนได้หรือไม่) | |

## ค. ข้อตกลงเมื่อให้คำตอบ

- คำตอบข้างต้นเป็นข้อมูลที่ถูกต้อง ณ วันที่ตอบ หากพบว่าตรวจวัดจริงไม่ตรงกับคำตอบ บริษัทฯ มีสิทธิ์ปฏิเสธรับสินค้าและขอคืนเงิน
- บริษัทฯ จะไม่พิจารณาใบเสนอราคาที่ไม่ตอบข้อ 1–8 ครบถ้วนเป็นลายลักษณ์อักษร

ขอแสดงความนับถือ
[ชื่อ ตำแหน่ง บริษัท ช่องทางติดต่อ]

## หมายเหตุสำหรับผู้ใช้แม่แบบ (ไม่ต้องส่งให้ผู้ขาย)

- **ข้อ 3 และ 4 เป็นข้อที่ตัดสินราคาและกำหนดการ** (doc 344 §5) ถ้าผู้ขายตอบว่าไม่มี EK certificate เครื่องยังได้ระดับ NATIVE-ELIGIBLE แต่จะไม่ได้ `APPLIANCE` ในอนาคต ให้ Steward ตัดสินตามบันทึกข้อเสนอคำตัดสินข้อ 1
- ถ้าผู้ขายไม่รู้คำตอบหรือส่งต่อให้ผู้ผลิต ให้ขอคำตอบจากผู้ผลิตโดยตรง หรือใช้ตัวอย่างวัดเอง อย่าเดา
- เก็บอีเมลตอบกลับต้นฉบับ (พร้อม header) เข้าแฟ้มจัดซื้อ ข้อ 1 ในมาตรฐานจัดซื้อ
