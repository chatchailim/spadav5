# ADR XXXX: ขอบเขตการรับรองฮาร์ดแวร์ SetBox — แบบเดี่ยว (ไม่เชื่อม SPADA) และแบบเชื่อมต่อ (เชื่อม SPADA)

## Authority

## Context

ADR 0020 กำหนดให้เครื่องติดตั้ง SetBox ได้ต่อเมื่อรุ่นอยู่ในทะเบียนฮาร์ดแวร์ (doc 344) โดยเกณฑ์คือ EK certificate เขียนจากมุมที่ SPADA ออกสิทธิ์ติดตั้งและตัดสิน `deviceAssurance` แต่ OneManOS SetBox ออกแบบให้ทำงานได้บนเครื่องเดียวโดยไม่เชื่อม SPADA (README ของ `onemanos-setbox`) และ ADR 0014 ตัดสินว่า OneManOS/OneVault/SetBox อยู่นอก SPADA จึงมีสองเส้นทางที่เป็นไปได้จริงและมีเหตุผลต่างกัน ขณะที่ทะเบียน doc 344 ยังว่างเปล่า

## Decision

### 1. สองเส้นทาง

| | **แบบเดี่ยว (Track S)** ไม่เชื่อม SPADA | **แบบเชื่อมต่อ (Track C)** เชื่อม SPADA |
|---|---|---|
| เหตุที่ต้องมีเกณฑ์ฮาร์ดแวร์ | ปกป้องข้อมูลและความต่อเนื่องของลูกค้ารายนั้น | SPADA ไว้วางใจตัวตนอุปกรณ์ ความผิดพลาดกระทบผู้อื่น |
| ผู้กำกับ/ผู้ลงนาม | ฉัตรชัย หลิมประเสริฐศิริ (ชั่วคราว) | Attestation Policy Steward (ADR 0019/0020) |
| ทะเบียน | **ทะเบียนแบบเดี่ยว** (ฝั่ง OneManOS, `onemanos-setbox`) | ทะเบียน doc 344 (ฝั่ง SPADA) |
| เกณฑ์ | **HB** (ข้อ 2) | ADR 0020 เต็ม |
| เครื่องที่ลูกค้ามีอยู่แล้ว | อนุมัติเป็นรายกรณีหลังวัดจริง (ข้อ 4) | ห้าม (ADR 0020) |

### 2. เกณฑ์ฐาน HB

HB = ระดับ NATIVE-ELIGIBLE ของ ADR 0020 §2: TPM 2.0 บนฮาร์ดแวร์จริง (vTPM ปฏิเสธเสมอ), Secure Boot เปิดและอยู่ใน user mode, PCR bank SHA-256 ครบ, อ่าน event log ได้, ปิดช่องดีบัก (DCI/JTAG) ถาวรได้ ใช้ขั้นตอนวัด 10 ข้อของ doc 344 §3 กับทั้งสองเส้นทาง ใช้เกณฑ์เดียวกันเพื่อให้เครื่องแบบเดี่ยวเชื่อม SPADA ภายหลังได้โดยไม่ต้องเปลี่ยนเครื่อง

### 3. ทะเบียนสองชุดและการรวม

ทะเบียนทั้งสองเป็น append-only แยกเจ้าของ **SPADA ไม่อ่านและไม่รับรองทะเบียนแบบเดี่ยว** (สอดคล้อง ADR 0014 และ doc 340 §11) เครื่องรายตัวย้ายเข้าทะเบียน doc 344 ได้เมื่อ:

1. เจ้าของเครื่องลงทะเบียนเป็นสมาชิกใน SPADA Node/Network (มี DID ตัวตนที่ยืนยันแล้ว และ TrustScore ≥ 500 ตามเกณฑ์ `ProvisioningClaim` ใน ADR 0017) และต้องการเชื่อมเครื่อง
2. Attestation Policy Steward วัดหรือทบทวน evidence ของเครื่องจริงนั้น ได้ระดับอย่างน้อย NATIVE-ELIGIBLE (ใช้ evidence เดิมได้เมื่อ BIOS และ TPM firmware เดียวกัน ตามดุลยพินิจ)
3. เพิ่มเป็นรายการใหม่ใน doc 344 ที่อ้างรายการเดิม ไม่ย้ายหรือลบของเดิม
4. provision ด้วย `ProvisioningClaim` ใหม่ (ADR 0017 §7.3–7.4)

การผสมสองทะเบียนเป็นชุดเดียวทั้งหมดเป็นการตัดสินใจแยกในอนาคต

### 4. เครื่องที่ลูกค้ามีอยู่แล้ว (แบบเดี่ยว) อนุมัติเป็นรายกรณี

ลูกค้าส่งรุ่น/serial/BIOS ก่อนตกลงสัญญา → วัดเครื่องจริง 10 ข้อ (ห้ามอนุมัติจากเอกสารหรือคำบอกเล่า) → ระดับต้องไม่ต่ำกว่า HB มิฉะนั้นปฏิเสธ → ผู้ลงนามบันทึกรายการพร้อมเหตุผลและ hash ของ evidence → ล้างเครื่องและติดตั้งจาก image ที่เซ็นแล้ว ล็อก BIOS ตามเวอร์ชันที่วัด → ลูกค้าลงนามรับทราบว่าเป็นเครื่องของลูกค้าและไม่ได้รับการรับรองจาก SPADA · ไม่ขยายผลเป็นรุ่นอื่นโดยอัตโนมัติ

### 5. เงื่อนไขเพิ่มเฉพาะแบบเดี่ยว

ตรวจ signature/manifest แบบ fail-closed ตอนติดตั้ง, เปิดการเข้ารหัสดิสก์ทั้งลูกและให้ลูกค้าถือ recovery key, บังคับ preflight ก่อนส่งมอบ, ผ่านตรวจ H1–H7, ซ้อมกู้คืน backup จริงก่อนส่งมอบ (สอดคล้องผลตรวจความพร้อม SetBox 2026-09-06 ซึ่งยังเป็น CONDITIONAL)

### 6. คำศัพท์และการสื่อสาร

- ใช้ชื่อไทยกำกับ "แบบเดี่ยว" และ "แบบเชื่อมต่อ" ในเอกสารที่ลูกค้าอ่าน ไม่ใช้ตัวย่อ S/C ลำพัง
- "แบบเดี่ยว/แบบเชื่อมต่อ" เป็นคำเชิงจัดซื้อและปฏิบัติการ **ห้ามนำไปใช้เป็นค่าใน schema หรือ API ของ SPADA** และไม่เกี่ยวกับ `T1/T2/T4-S` ของ OneManOS (doc 340 §11)
- สัญญาแบบเดี่ยวต้องระบุว่า "ไม่ได้รับ `deviceAssurance` หรือการรับรองใดจาก SPADA"

## Consequences

**ข้อดี**: รักษาขอบเขต ADR 0014, ไม่ล็อกเครื่องลูกค้า, ใช้ขั้นตอนวัดเดียว, เครื่องแบบเดี่ยวเชื่อม SPADA ภายหลังได้โดยไม่ต้องเปลี่ยนเครื่อง
**ต้นทุน/ความเสี่ยง**:
- ต้องดูแลทะเบียนสองชุดและกำหนดผู้ลงนามสองสาย ปัจจุบันเป็นบุคคลเดียวกัน (รวมอำนาจ) ควรมีผู้สำรองและผู้ตรวจ evidence คนที่สองเมื่อมีคน
- ต้องมีสคริปต์รับรองฮาร์ดแวร์ (doc 344 ระบุว่ายังไม่มี ต้องมี WO)
- ทะเบียนยังว่างเปล่า จึงยังไม่มีรุ่นใดติดตั้งได้ตามกติกาทั้งสองเส้นทางจนกว่าจะมีรายการแรก
- ลูกค้าอาจเข้าใจผิดว่าแบบเดี่ยวได้รับการรับรองจาก SPADA (ลดด้วยสัญญาและข้อความบนเอกสารส่งมอบ)

## Follow-up

1. ตั้งทะเบียนแบบเดี่ยวใน `onemanos-setbox` (แม่แบบ: `HARDWARE-REGISTRY-STANDALONE-TEMPLATE.md` ใน spadav5)
2. WO สคริปต์รับรองฮาร์ดแวร์ที่ใช้ได้ทั้งสองเส้นทาง
3. ระบุผู้สำรองและผู้ตรวจ evidence คนที่สอง
4. ปรับสัญญามาตรฐานแบบเดี่ยว
5. ทบทวน ADR นี้เมื่อมีสมาชิกลงทะเบียนใน node อื่นและเมื่อ doc 344 มีรายการแรก
