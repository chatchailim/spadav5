## Context

doc 100 (Sustainable Economics & Revenue Model v5.0, 2026-01-02, ระบุ "Official - Authoritative") อธิบายโทเคน SPADA, staking, smart contract เก็บค่าธรรมเนียม, treasury, DAO กำหนดค่าธรรมเนียม, ตลาดข้อมูล anonymized, และส่วนแบ่ง node ตายตัว 40% ซึ่งขัดกับ ADR 0012 (Accepted 2026-08-26: external ledger/sidechain อยู่ที่ L3 เท่านั้น ไม่ใช่ Core และยังไม่มีโค้ด) และแนวทาง share-on-request ของ `data-share-broker-service` นอกจากนี้ ประมาณการรายได้และจุดคุ้มทุนใน doc 100, 228 และ 248 ขัดกันเอง และ doc 189 ระบุว่ายังไม่มีผู้ใช้/LOI ที่ verify ได้ กำลังจะมีการระดมทุน

## Decision (ข้อเสนอ ทางเลือก A แล้ว C)

1. **โทเคน, staking, smart contract เก็บค่าธรรมเนียม, DAO กำหนดค่าธรรมเนียม และตลาดข้อมูล anonymized ไม่เป็นแกนของโมเดลเศรษฐกิจ** และห้ามปรากฏในเอกสารลงทุนเป็นรายได้หลัก หากในอนาคตมีบริการที่ใช้ external ledger ให้เป็นบริการ L3 แบบ optional ตาม ADR 0012 และต้องผ่านการตรวจด้านกฎหมายก่อนเสนอต่อผู้ลงทุน
2. **การขายข้อมูล** ทำได้เฉพาะแบบ share-on-request ที่เจ้าของสั่งเองต่อครั้ง ไม่ copy ถาวร ตามกลไกของ broker (ADR 0005, `data-share-broker-service`)
3. **ส่วนแบ่ง node และค่าธรรมเนียมทั้งหมด** ตามตารางค่าธรรมเนียมที่ประกาศ ล็อกด้วยหลักฐานและมีเพดาน (Fee Constitution ใน MEMBER-ECONOMY) ไม่ตายตัวที่ 40%
4. **ตัวเลขรายได้ ผู้ใช้ และจุดคุ้มทุนทั้งหมดเป็น "ประมาณการเชิงสถานการณ์"** ต้องมีป้ายกำกับ ห้ามอ้างเป็นข้อเท็จจริงและต้องไม่ขัดกันข้ามเอกสาร จนกว่าจะมีโมเดลเดียวที่ตรวจสอบได้ (ทางเลือก C ภายหลังนำร่อง E1)
5. **เอกสารลงทุนทุกฉบับ** ต้องตรวจก่อนเปิดห้องข้อมูลและใช้ภาษาตามสถานะ doc 189 (VERIFIED / TO VERIFY / CONTRADICTED / ASPIRATIONAL)
6. เพิ่ม ADR ที่ Accepted ในลำดับศักดิ์ของ doc 244 Resolution 4 (ADR ที่ตัดสินแล้วอยู่เหนือเอกสารทั่วไป) *(รอ Lead ตัดสินเป็นข้อแยก)*
7. ใส่ banner ที่ doc 100 (และเอกสารที่คัดตัวเลขมา) ว่า "Aspirational / บางส่วนถูกแทนที่โดย ADR นี้" พร้อมลิงก์

## Consequences

**ข้อดี**: ลดความขัดแย้งกับ ADR 0012 และแนวทางปกป้องข้อมูล, ลดความเสี่ยงที่นักลงทุนพบตัวเลขขัดกัน, สอดคล้องกับข้อเสนอเศรษฐกิจสมาชิก
**ต้นทุน/ความเสี่ยง**:
- ต้องแก้และตรวจเอกสารหลายฉบับ (ผมยังไม่ได้ตรวจทุกฉบับใน `docs/`)
- เรื่องเล่า (narrative) ต่อนักลงทุนอาจลดความน่าตื่นเต้นลงจากการถอดโทเคน/staking
- ถ้ามีเอกสารส่งออกไปแล้ว อาจต้องพิจารณาการแจ้งแก้ไข
- ยังไม่มีตัวเลขใหม่จนกว่าจะมีข้อมูลนำร่อง

## Follow-up

1. ใส่ banner ใน doc 100 และเอกสารที่เกี่ยวข้อง
2. ตรวจเอกสารลงทุนทั้งหมดและบันทึกผลตรวจ
3. ปรึกษากฎหมายเรื่องโทเคน/staking/ตลาดข้อมูล/เครดิต
4. เขียนโมเดลเศรษฐกิจใหม่ (ทางเลือก C) หลังมีข้อมูลนำร่อง
5. ปรับ doc 244 Resolution 4 (ถ้า Lead เห็นชอบ)
