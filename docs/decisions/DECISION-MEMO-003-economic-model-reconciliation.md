# บันทึกเสนอคำตัดสิน: โมเดลเศรษฐกิจ doc 100 ขัดกับสถาปัตยกรรมและเอกสารอื่น จะจัดการอย่างไร

- **รหัสเอกสาร: SPD-DEC-003**
- สถานะ: **Lead อนุมัติทางเลือก A แล้ว C (2026-09-29)** ตามข้อเสนอ · รายละเอียดคำตัดสินอยู่ใน [SPD-DEC-004](DECISION-004-current-fundraising-offer-and-terms.md) ข้อ 8 · ข้อ 6.4 (ผู้ตรวจเอกสารลงทุนและกำหนดวัน) ยังต้องระบุชื่อ · วันที่ 2026-09-29
- ต่อยอดจาก: [GAP-ANALYSIS](../GAP-ANALYSIS.md) ข้อ 3 · [MEMBER-ECONOMY](../MEMBER-ECONOMY.md) · ADR 0012, 0005, 0026 · doc 189 · doc 244
- **เหตุด่วน**: กำลังจะมีการระดมทุน เอกสารลงทุนต้องไม่ขัดกันเองและไม่ขัดกับระบบจริง
- ข้อมูลมาจากการอ่านและค้นคำสำคัญใน `spada-monorepo` @ `206d1f9` ผมไม่ได้ตรวจเอกสารทุกฉบับใน `docs/` และไม่ได้ให้คำแนะนำด้านกฎหมายหรือการเงิน

---

## 1. สรุปสำหรับผู้ตัดสินใจ

**ปัญหา 2 ชั้น**

1. **doc 100 ขัดกับ ADR ที่ตัดสินแล้ว**: มีโทเคน SPADA, staking, smart contract เก็บค่าธรรมเนียม, DAO กำหนดค่าธรรมเนียม, ตลาดข้อมูล anonymized ซึ่งขัดกับ ADR 0012 (ไม่มีกลไก chain/โทเคนใน Core และตรวจโค้ดแล้ว 0 hit) และแนวทาง share-on-request
2. **ประมาณการรายได้ในเอกสารต่างฉบับ ขัดกันเอง** (ดูตารางข้อ 3) ซึ่งเป็นเรื่องที่นักลงทุนจะเห็นได้ทันทีเมื่อเปิดห้องข้อมูล (data room)

**คำแนะนำ**: ทางเลือก **A** (แยกชั้น) ทำตอนนี้ แล้วทำ **C** (เขียนโมเดลใหม่จากข้อมูลนำร่อง) ภายหลัง เหตุผลอยู่ในข้อ 5

## 3. ทางเลือก

| | **A. แยกชั้น (แนะนำทำตอนนี้)** | B. คงทั้งหมดเป็นอนาคต | C. เขียนโมเดลใหม่ทั้งฉบับก่อนระดมทุน |
|---|---|---|---|
| เนื้อหา | คงรายได้ระดับบริการ (subscription, enterprise, ธุรกรรม, คอมมิชชันแอปภายใต้เพดาน) · **ยกเลิกในฐานะแกนหลัก**: โทเคน/staking/DAO กำหนดค่าธรรมเนียม/smart contract เก็บค่าธรรมเนียม/ตลาดข้อมูล anonymized · ส่วนแบ่ง node ตามตารางค่าธรรมเนียมที่ประกาศและมีเพดาน (ไม่ตายตัว 40%) · ตัวเลขทั้งหมดติดป้ายเป็น "ประมาณการสถานการณ์ (scenario)" | ติดป้าย "Phase อนาคต" ทั่วทั้ง doc 100 | สร้างโมเดลเดียวที่ตรวจสอบได้จากข้อมูลจริงและทดลองนำร่อง |
| ข้อดี | เร็ว ลดความขัดแย้งกับ ADR และลดความเสี่ยงต่อนักลงทุน | เร็วที่สุด | แข็งแรงที่สุด นักลงทุนตรวจได้ |
| ข้อเสีย | ยังไม่ได้ตัวเลขใหม่ | ยังขัดกับ ADR 0012 และผู้อ่านอาจเข้าใจเป็นแผนหลัก | ใช้เวลา และตอนนี้ยังไม่มีข้อมูลนำร่อง (user/LOI = 0) |
| ความเสี่ยงต่อนักลงทุน | ต่ำ (ถ้าติดป้าย scenario ชัด) | **สูง** | ต่ำสุด แต่อาจไม่ทันกำหนด |

**คำแนะนำ: A ทันที + C หลังได้ข้อมูลจากนำร่อง E1 (SetBox รายแรก)** เพราะ

1. ADR 0012 ตัดสินแล้วและมีผลเหนือเอกสารลงทุน ต้องไม่ให้เอกสารใดเสนอโทเคนเป็นแกนหลัก
2. ตัวเลขที่ขัดกันสามฉบับ ต้องแก้ก่อนห้องข้อมูลเปิด แต่การตัดสินตัวเลขจริงทำได้ก็ต่อเมื่อมีข้อมูล
3. โทเคน/staking/ตลาดข้อมูลมีประเด็นกฎหมายที่ต้องปรึกษาผู้เชี่ยวชาญก่อนเสนอให้ผู้ลงทุน

## 6. สิ่งที่ Lead ต้องตัดสิน (ตอบเป็นข้อ)

1. เลือกทางเลือก **A / B / C** (แนะนำ A แล้ว C)
2. ยืนยันว่าโทเคน/staking/DAO กำหนดค่าธรรมเนียม/ตลาดข้อมูล anonymized **ไม่เป็นแกนของโมเดลเศรษฐกิจ** และไม่ปรากฏในเอกสารลงทุนเป็นรายได้หลัก
3. ให้ส่วนแบ่ง node เป็นไปตามตารางค่าธรรมเนียมที่ประกาศและมีเพดาน (Fee Constitution) แทน 40% ตายตัว
4. มอบหมายผู้ตรวจเอกสารลงทุนก่อนเปิดห้องข้อมูล และกำหนดวัน
5. เพิ่มลำดับศักดิ์ของ ADR ใน doc 244 หรือไม่

**ลายเซ็นตัดสิน** (Lead): ______________________ วันที่ ____________ · ข้อที่แก้ไขจากข้อเสนอ: ______________________

## 7. สิ่งที่ผมไม่ทราบ

- สถานะปัจจุบันของตัวเลขใน doc 189 และเอกสารลงทุนฉบับล่าสุดที่ส่งให้ผู้ลงทุนแล้ว (ถ้ามี)
- ว่าเอกสารใดถูกส่งออกไปข้างนอกแล้วบ้าง (ถ้าส่งแล้ว ต้องพิจารณาการแจ้งแก้ไข)
- ผลทางกฎหมายและภาษีของโทเคน/staking/ตลาดข้อมูล
