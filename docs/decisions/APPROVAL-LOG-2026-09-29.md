## สิ่งที่การอนุมัตินี้ **ไม่ได้ทำให้เสร็จ** (ยังต้องมีคนลงมือ/กรอก)

| รายการ | ผู้ทำ | สถานะ |
|---|---|---|
| ส่งจดหมาย RFQ ให้ผู้ขายจริง | ผู้จัดซื้อ (ยังไม่ระบุชื่อ) | ยังไม่ส่ง · ผมส่งแทนไม่ได้ |
| ออกใบงาน S1–S3 ใน `spada-monorepo` และตรวจ ACTIVE CLAIMS | ผู้ดูแล/agent ที่ถือ claim | ยังไม่ออก · ผมมีสิทธิ์อ่านอย่างเดียวใน monorepo |
| นำ ADR ขอบเขต ADR 0020 เข้า `architecture/adr/` ด้วยเลขที่ว่าง | Cowork/ผู้ดูแล ADR | รอ (มีไฟล์พร้อมนำเข้า) |
| ตั้งทะเบียนแบบเดี่ยวใน `onemanos-setbox` | ผู้ดูแล repo | รอ (มีแม่แบบพร้อม) |
| ชื่อผู้รับผิดชอบ P1–P5, S1–S3, ผู้สำรอง, ผู้ตรวจ evidence คนที่สอง, วันกำหนด | Lead | **ต้องกรอก** |
| กรอกแบบ Purchase-Time Decision Sheet | ผู้จัดซื้อ/ผู้อนุมัติจ่าย | ทำ ณ วันซื้อหลังระดมทุน |
| ปรึกษากฎหมาย: จัดซื้อ/ภาษี/ศุลกากร, โทเคน/staking/ตลาดข้อมูล/เครดิต | ที่ปรึกษากฎหมาย | ยังไม่ทำ · ผมไม่ได้ให้คำแนะนำทางกฎหมาย |
| การเขียน OTP/ล็อก secure boot ของ KeySign | Lead (เมื่อครบ 6 เงื่อนไข) | **ห้ามทำ** จนกว่าจะครบเงื่อนไข |
| ตัดสินเรื่องอื่นที่ค้าง: doc 100 vs ADR 0012, ADR 0024–0026, doc 340 §10 (SLA/RPO/RTO, ความรับผิด), การแยกทายาท/ผู้พิทักษ์ (ADR 0019) | Lead | **ยังไม่ครอบคลุมโดยการอนุมัตินี้** ผมไม่ตีความคำอนุมัติกว้างเกินขอบเขต |

## เงื่อนไขมีผล

- ข้อ A6/A7 มีผลกับการซื้อและติดตั้งที่จะเกิดหลังได้รับเงินระดมทุน ก่อนซื้อจริงให้ทบทวนมาตรฐานหนึ่งรอบ (มาตรฐานข้อ 13)
- ระหว่างนี้ **ทะเบียนฮาร์ดแวร์ยังว่างเปล่า** จึงยังติดตั้ง SetBox ตามกติกาไม่ได้ทั้งสองเส้นทางจนกว่าจะมีรายการแรก

## ข้อสังเกตที่ควรรักษาไว้

- Lead ถืออำนาจทั้งฝั่ง SPADA (Steward) และแบบเดี่ยว (ผู้ลงนาม) ชั่วคราว ให้ลดความเสี่ยงตามข้อเสนอ: ผู้ขอซื้อ/ผู้จัดซื้อ/ผู้จ่ายเงินแยกคนกัน, มีผู้ตรวจ evidence คนที่สองเมื่อมีคน, กำหนดผู้สำรอง
