# ส่วน A: วิธีใช้เอกสารนี้เป็นแม่แบบสำหรับโครงการใหม่

## A.1 ขั้นตอนเริ่มโครงการใหม่ (ทำซ้ำได้)

1. คัดลอกไฟล์นี้เป็น `docs/designspec.md` ของโครงการใหม่ เปลี่ยนรหัสเอกสารและเวอร์ชัน
2. กรอก **B.1 โปรไฟล์โครงการ** (ใช้เวลา ≤ 1 ชั่วโมง ถ้ากรอกไม่ได้ แปลว่ายังไม่พร้อมเริ่ม)
3. เลือกบทบาทและใส่ชื่อคนจริงใน **C.1** (หนึ่งบทบาทต้องมีชื่ออย่างน้อยหนึ่งคน และผู้อนุมัติต้องไม่ใช่ผู้ทำงานเดียวกัน)
4. ตั้ง repo ตามโครงสร้างใน **H.1** แล้วติดตั้ง CI ขั้นต่ำตาม **H.3** ก่อนเขียนโค้ดบรรทัดแรก
5. สร้างทะเบียนความต้องการ (**E**) จากแม่แบบ **K.2** และเริ่มที่ระยะ **P0** (ดู D)
6. ทุกระยะจบด้วยประตู (Gate) ที่มีมนุษย์ระบุชื่ออนุมัติ บันทึกใน `docs/decisions/`

## A.2 หลักการ 8 ข้อของกรอบนี้

1. **เอกสารมาก่อนโค้ด แต่ไม่เกินจำเป็น:** ทุกงานมีรหัสเอกสาร (`SPD-<ประเภท>-<เลข>`) และอยู่ในสารบัญ
2. **มนุษย์ระบุชื่ออนุมัติงานที่ย้อนกลับไม่ได้เสมอ:** agent ไม่อนุมัติแทน (กรอบ D2.1 ของ SPADA)
3. **หลักฐานก่อนคำกล่าวอ้าง:** "ผ่าน" ต้องมีลิงก์ run/ไฟล์ผลลัพธ์/คอมมิต ไม่ใช่ความรู้สึก
4. **ซื่อตรงเรื่องสถานะ:** แยก "มีจริง / ข้อเสนอ / ยังไม่ตรวจ" ในทุกเอกสาร (EGO-VOID: ชี้ช่องว่างและความเสี่ยง ไม่ประจบ)
5. **ลดการสะสมงานค้าง:** commit/PR เล็ก, ปิดเรื่องแล้วย้ายลงทะเบียน "ปิดแล้ว" ห้ามลบแถว
6. **ออกแบบให้ตรวจสอบได้:** CI + หลักฐานเทสต์ + บันทึกการตัดสิน
7. **ความเป็นเจ้าของข้อมูลของผู้ใช้ก่อน:** ส่งออก/เพิกถอน/ออฟไลน์เห็นได้เสมอ
8. **เริ่มเล็ก พิสูจน์ แล้วขยาย:** ทุกระยะมีเกณฑ์ผ่านที่วัดได้ ไม่ขยายขอบเขตโดยไม่ลบอะไรออก

# ส่วน F: การออกแบบระบบ (Design)

## F.1 สถาปัตยกรรม 5 ชั้นของ SPADA (กฎ: เรียกได้เฉพาะชั้นที่อยู่ติดด้านล่าง)

```
L5 MyAI        Personal AI (on-device)         เรียกลงผ่าน BookChain เท่านั้น
L4 BookChain   5-Book distributed ledger        (ไม่ใช่ blockchain)
L3 Service     บริการ/MCP adapters/gateway
L2 Space       PersonSpace / WorkSpace / OfficeSpace
L1 Place       DID, Zero-Trust, biometric, quantum-safe
```

กฎเหล็กของ SPADA (จาก `CLAUDE.md` ของ monorepo) ที่ต้องคงไว้เมื่อนำกรอบนี้ไปใช้ในโครงการ SPADA: MyAI on-device only · ห้ามคำว่า "blockchain" · ห้าม layer-skip · ตรวจ DID ownership ก่อนเข้า PersonSpace · ตรวจ TrustScore ก่อนงานอ่อนไหว (300/500/700/900) · บันทึก audit ทุก state-change · เข้ารหัส quantum-safe กับข้อมูลอ่อนไหว

## F.2 SetBox: ส่วนประกอบและเส้นทาง

| ส่วน | บทบาท | สถานะ |
|---|---|---|
| PC1 / PC1+PC2 / PC1+PC2+PCn | ผังติดตั้งทางกายภาพ; PC2/PCn เชื่อมผ่าน bridge (`onevault-mcp`) ไม่มีกุญแจ/คลังของตัวเอง | **[มีจริง]** |
| `business-api` / คลังเอกสาร (DMS) | จุดผ่านเดียวไปยังข้อมูล ไม่ต่อฐานข้อมูลตรง | **[มีจริง]** |

## F.3 การจัดซื้อและรับรองรุ่นฮาร์ดแวร์ D0–D8 (SPD-PRC-001, มีผลหลังได้รับเงินระดมทุน)

D0 สเปกขั้นต่ำ → D1 RFQ + คำถามบังคับ (ลายลักษณ์อักษร) → D2 ประเมินคำตอบ → D3 ตัวอย่าง 1–2 เครื่อง → D4 วัดและรับรองรุ่น (ทะเบียน append-only: `APPLIANCE-CANDIDATE / NATIVE-ELIGIBLE / REJECTED`) → D5 PO ล็อต → D6 ตรวจรับ+สุ่มวัดซ้ำ → D7 provision + H1–H7 → D8 ดูแลหลังขาย (อัปเดต BIOS = รับรองใหม่) · ไม่ผ่านการรับรอง ไม่ออก PO ล็อต · ธงแดงให้หยุดและรายงาน Steward

## F.4 บันไดแอป (SPD-PLN-004) **[ข้อเสนอ ADR 0026 ยัง Proposed]**

# ส่วน G: UX/UI Spec

> แหล่งต้นฉบับ: SPD-MED-008 (Harness) และ SPD-MED-007 (KeySign) ภาพทั้งหมดในต้นฉบับเป็นภาพจำลอง **[ข้อเสนอ ยังไม่ผ่านทดสอบกับผู้ใช้จริง]** ยกเว้นหน้าจอ DMS ของ setbox ที่มีโค้ดจริง

## G.1 หลักออกแบบ 12 ข้อ (บังคับ)

1. **อนุมัติที่ตัวตน:** งานเสี่ยงอนุมัติได้เฉพาะ KeySign ไม่มีปุ่มอนุมัติบนมือถือ/โน้ตบุ๊ก/การแจ้งเตือน
2. **แสดงก่อนทำ:** ใครขอ ขออะไร เสี่ยงแค่ไหน ย้อนกลับได้ไหม ก่อนทุกการอนุมัติ
3. **ข้อมูลน้อยที่สุด:** แสดง `dataScopes` + `purpose` ก่อนติดตั้ง สิทธิ์อ่อนไหวปิดเป็นค่าตั้งต้น
4. **ย้อนกลับได้เป็นค่าตั้งต้น:** ขั้น A มีปุ่มย้อน; ขั้นย้อนไม่ได้เตือนชัด
5. **ไม่ซ่อนความผิดพลาด:** แสดงเมื่อ MyAI ทำพลาดและบันทึกบทเรียน
6. **หลักฐานอยู่ใกล้งาน:** บันทึกหลักฐานแสดงข้างงาน ไม่ซ่อนในเมนูลึก
7. **ภาษาคน:** ใช้ "ย้อนกลับไม่ได้" แทน irreversible ไม่ใช้ศัพท์เทคนิคกับผู้ใช้ปลายทาง
8. **ไม่เร่ง:** ไม่ใช้ตัวนับเวลาบีบ ยกเว้นกำหนดจริง (เช่น 15 วินาทีของการกด KeySign)
9. **ไม่กดดันด้วยคะแนน:** ไม่เทียบกับคนอื่น ไม่ทำเป็นเกมแข่ง
10. **ออฟไลน์ก่อน:** ร่างได้ ซิงก์ทีหลัง บอกสถานะชัด
11. **เข้าถึงได้:** เสียง/ตัวอักษรใหญ่ ลดการเคลื่อนไหวได้ ไม่พึ่งสีอย่างเดียว
12. **ความเป็นเจ้าของ:** ปุ่ม "ส่งออกข้อมูล" และ "เพิกถอนสิทธิ์" เห็นได้เสมอ

**ข้อห้าม:** ปุ่ม "อนุมัติทั้งหมด" สำหรับงาน B/C · อนุมัติอัตโนมัติจากระยะไกล · ซ่อนสิทธิ์อ่อนไหวในรายการยาว · การแจ้งเตือนที่มีปุ่มอนุมัติ · ใช้ชื่อบัญชี agent เป็นผู้อนุมัติ

## G.4 ส่วนประกอบ (Components) ที่ต้องมี

บทสนทนา (bubble) · การ์ดแผน + แถวขั้น (ป้าย Tier, สถานะ: รอ/ทำ/เสร็จ/รออนุมัติ) · **การ์ดขออนุมัติ (ไม่มีปุ่มอนุมัติ ชี้ไปที่ KeySign)** · ปมหลักฐาน (ด้ายกรรม) · วงแหวน TrustScore · แถบข้อมูลอิสระตามประเภทงาน · การ์ดสิทธิ์ข้อมูล (scope + purpose) · ปุ่มส่งออก/เพิกถอน · ป้ายสถานะออฟไลน์/ซิงก์

## G.5 หน้าจอและแผนผังนำทาง (ย่อ; รายการเต็ม 18 ภาพดู SPD-MED-008 §6)

| รหัส | หน้าจอ | อุปกรณ์ | ระบบหลังบ้านที่เกี่ยวข้อง | หลักฐานที่บันทึก |
|---|---|---|---|---|

| N3 | พื้นที่ทำงาน (สั่ง/ดูแผน) | โน้ตบุ๊ก | MyAI → BookChain → Service | ปมหลักฐานต่อขั้น |
| N4 | ขออนุมัติ (ชี้ไปนาฬิกา) | โน้ตบุ๊ก | ISPADAActorAssertion + KeySign | ลายเซ็น + counter |

| KeySign | รอคำขอ → ตรวจ → กดค้าง → ผลลัพธ์ | นาฬิกา 240×240 | PKT-R5/R7 | ลายเซ็น |

## G.6 โฟลว์หลักที่ต้องออกแบบและทดสอบ

1. **ติดตั้งแอป (≤ 4 การแตะ):** ค้น → ดูสิทธิ์ข้อมูล → ยินยอม → ติดตั้ง
2. **สั่งงานกับ MyAI:** สั่ง → แผนเป็นขั้นพร้อมป้าย A/B/C → ขั้น A ทำเอง → ขั้น B การ์ดขออนุมัติ → นาฬิกา → ผลลัพธ์ + หลักฐาน
3. **อนุมัติบน KeySign:** แจ้งเตือน (ไม่เปิดรายละเอียดบนหน้าจอล็อก) → ตรวจสิ่งที่ขอ → กดค้าง → สำเร็จ/ปฏิเสธ
4. **เจ้าหน้าที่แก้เอกสาร (DMS):** เปิดเอกสาร → แก้ในฟอร์ม → ให้เหตุผล → บันทึกเป็นเวอร์ชันถัดไป → ถ้าเวอร์ชันชน ระบบปฏิเสธและบอกชัด
5. **เพิกถอน/ส่งออก:** เข้าถึงได้จากทุกหน้าที่เกี่ยวข้องกับข้อมูล

## G.7 สถานะหน้าจอที่ต้องมีทุกหน้า

| สถานะ | ต้องแสดง | ตัวอย่างข้อความ (ภาษาคน) |
|---|---|---|
| ว่าง | อธิบาย + ปุ่มเริ่ม | "ยังไม่มีเอกสาร เริ่มสร้างฉบับแรก" |
| กำลังโหลด | ไม่บล็อกทั้งหน้า | — |
| ผิดพลาด | เกิดอะไร + ทำอะไรต่อ + ไม่โทษผู้ใช้ | "บันทึกไม่สำเร็จ ข้อมูลของคุณยังอยู่ ลองใหม่ได้" |
| ออฟไลน์ | ป้ายชัด + ร่างยังใช้ได้ | "ออฟไลน์: ร่างจะซิงก์เมื่อเชื่อมต่อ" |
| ถูกปฏิเสธ | เหตุผล + ใครแก้ได้ | "ต้องให้ผู้อนุมัติที่เป็นคนยืนยัน" |
| ข้อมูลสาธิต | ป้ายเตือนชัดทุกหน้า | "ตัวเลขนี้เป็นตัวอย่าง ไม่ใช่ผลของฐานข้อมูลคุณ" |

## G.8 การแจ้งเตือน

สี: ข้อมูล = ฟ้า · ต้องดำเนินการ = ทอง · สำเร็จ = เขียว · เตือน/ปฏิเสธ = แดง · **ไม่มีปุ่มอนุมัติ** · ไม่เปิดรายละเอียดบนหน้าจอล็อก · จำกัดความถี่ · ช่องทาง push ต้องตัดสิน PDPA **[ต้องตัดสิน]**

## G.9 การเข้าถึงและเนื้อหา

เสียง/ตัวอักษรใหญ่ รองรับผู้สูงอายุ ลดการเคลื่อนไหว ไม่พึ่งสีอย่างเดียว · ภาษาไทยเป็นหลัก คงศัพท์เฉพาะของโครงการเป็นอังกฤษ ไม่แปลชื่อเฉพาะ · ทุกข้อความผิดพลาดบอกขั้นต่อไป

## G.10 การทดสอบ UX (ต้องทำก่อนเรียกว่าพร้อมใช้)

- ผู้ใช้จริง 5 คนต่อกลุ่ม (รวมผู้สูงอายุ/ผู้ไม่ถนัดเทคโนโลยี) · ไม่ให้อ่านคู่มือก่อน
- วัด: อัตราที่เข้าใจป้าย A/B/C · อัตราที่รู้ว่าอนุมัติที่ไหน · อัตราที่อ่านสิทธิ์อ่อนไหวก่อนยินยอม · เวลาติดตั้งแอปแรก
- เกณฑ์ผ่าน (H0): ผู้ใช้เข้าใจ A/B/C และรู้ว่าอนุมัติที่ไหนโดยไม่ต้องอ่านคู่มือ **[เกณฑ์เป็นข้อเสนอ ยังไม่มีตัวเลขเป้าหมาย ต้องตัดสิน]**
- ลำดับสร้าง: H0 ต้นแบบคลิกได้ → H1 เว็บ (N1,N2,N7,N8) ต่อทะเบียนจริง → H2 มือถือ + แจ้งเตือน → H3 KeySign → H4 Journey Studio → H5 Catalog สาธารณะ (ADR 0026)

# ส่วน H: วิศวกรรม, CI/CD และคุณภาพ

## H.1 โครงสร้าง repo มาตรฐาน

```
README.md                    ลิงก์สารบัญ + สถานะสั้น ๆ
docs/INDEX.md                สารบัญ + ทะเบียนงานค้าง/ปิดแล้ว (SPD-IDX-001)
docs/designspec.md           ไฟล์นี้
docs/decisions/              ADR, คำตัดสิน, ข้อยกเว้น
docs/work-orders/            ใบงานและผลตรวจรับ
docs/handoffs/ หรือ .agents/ ใบมอบหมายระหว่าง agent
docs/patches/                patch ที่เตรียมไว้ให้คนนำไปใช้ (เมื่อ agent เขียน repo ปลายทางไม่ได้)
scripts/                     เครื่องมือตรวจ/ประกอบ
.github/workflows/           CI/CD
.github/PULL_REQUEST_TEMPLATE.md
```

## H.2 มาตรฐาน commit / PR

- PR เล็ก หนึ่งเรื่อง มีหัวข้อ Summary / ผลกระทบความปลอดภัย-ความเป็นส่วนตัว-ความเข้ากันได้ (ตาม template ของ setbox: ติ๊ก tests ผ่าน, ไม่มีความลับ/PII/ฐานข้อมูล, บันทึกความเข้ากันได้ของ schema, อัปเดตเอกสารและ manifest, **DCO sign-off**)
- DCO เป็นการรับรองของมนุษย์: agent ไม่ใส่แทน (ตามที่ PR #13 ระบุ)
- ผู้ตรวจต้องไม่ใช่ผู้เขียน ผู้เขียน = AI ไม่นับเป็นการตรวจอิสระ
