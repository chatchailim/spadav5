# ADR-0009: Offline และ mesh resilience

- สถานะ: Proposed
- วันที่: 2026-09-29
- ระยะ: P2
- ผู้ตัดสินใจ: (รอกำหนด)

## บริบท
ผู้ใช้ในพื้นที่ห่างไกลหรือช่วงภัยพิบัติอาจไม่มีอินเทอร์เน็ต ระบบต้องยังใช้งานขั้นพื้นฐานได้

## ทางเลือกที่พิจารณา
1. ต้องออนไลน์เสมอ
2. Store-and-forward + mesh/LoRa/sneakernet พร้อมกลไกรวมสถานะภายหลัง

## การตัดสินใจ (ข้อเสนอ)
เลือกข้อ 2: ธุรกรรมและ consent ลงนามออฟไลน์แล้วซิงก์ภายหลัง มีกติกาแก้ความขัดแย้ง (เช่น double-spend ในช่วงออฟไลน์ ด้วยวงเงินจำกัดต่อช่วง) และเส้นทางส่งต่อผ่าน Relay

## ผลที่ตามมา
ข้อดี: ครอบคลุมผู้ใช้มากขึ้น ทนภัยพิบัติ ข้อเสีย: มีความเสี่ยงการใช้ซ้ำในช่วงออฟไลน์ ต้องจำกัดวงเงินและตรวจสอบภายหลัง

## เกณฑ์ตรวจรับ
- ธุรกรรมออฟไลน์ภายในวงเงินสำเร็จและตรวจสอบได้ภายหลัง
- ทดสอบการซิงก์หลังเครือข่ายขาดนานตามสถานการณ์ที่กำหนด

## คำถามที่ยังเปิดอยู่
- วงเงินออฟไลน์และเวลาสูงสุด
- คลื่น/ข้อกำหนดกฎหมายวิทยุสำหรับ LoRa/mesh
