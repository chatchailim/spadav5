# SPADA Harness: UX/UI การทำงานร่วมกันของ MyAI กับเจ้าของ (โลกคู่ขนานและกฎแห่งกรรมดิจิทัล)

**รหัสเอกสาร:** SPD-MED-008 · **สถานะ:** ข้อเสนอ UX/ภาพจำลองแนวคิด (ยังไม่ผ่านผู้ตรวจ ไม่ใช่แอปที่รันจริง) · **วันที่:** 2026-10-02
**อ้างอิง:** SPD-ANL-004, doc 034 (Autonomy), doc 160/162 (Soul.md/Soul-Aligned), doc 263 (OPB OS), ADR 0002 (TrustScore ฝั่งเซิร์ฟเวอร์), ADR 0024 (Genesis, Proposed), ADR 0014/0016, D2.1, SPD-MED-007 (KeySign UX)
**วิดีโอประกอบ:** spada-harness-myai-ux (240 วินาที ไม่เก็บใน repo)

## 1. โจทย์และข้อควรรู้
เจ้าของต้องการ UX แบบ "Harness AI App" ตามมาตรฐานทั่วไป (บทสนทนา + แผนงาน + การเรียกเครื่องมือ + ขออนุมัติ + บันทึกกิจกรรม) แต่ให้มีเอกลักษณ์ของ SPADA คือเป็น **เศรษฐกิจดิจิทัลที่ขนานไปกับโลกจริง** และมี **กฎแห่งกรรมดิจิทัล** ที่ยุติธรรมกว่า

**ข้อควรรู้ที่ตรวจแล้ว**
1. **TrustScore ที่มีในโค้ด** คำนวณฝั่งเซิร์ฟเวอร์จากเหตุการณ์ใน TrustedBook (ADR 0002) ผู้เรียกส่งคะแนนเองไม่ได้ เกณฑ์ที่กำหนดในโค้ด: SERVICE_CALL 300, SENSITIVE 500, AUTONOMOUS 700, CROSS_NODE_FEDERATION 900 (ADR 0024) ตัวอย่างเหตุการณ์ที่ให้คะแนนมีเพียง MEMBER_REGISTERED +50 และ MEMBER_REFERRAL +25 ดังนั้น **คะแนน 480 → 505 ในวิดีโอเป็นตัวเลขตัวอย่างเพื่ออธิบาย** ไม่ใช่กติกาจริง
2. **ADR 0024 ยังเป็น Proposed** (Genesis โดยผู้ดูแล node) ส่วนระดับอิสระ L0–L5 ใน doc 034 ขัดกับ D2.1 (อิสระเฉพาะงานที่ย้อนกลับได้) ภาพจึงยึด D2.1: งานย้อนกลับไม่ได้ต้องมีมนุษย์ระบุชื่ออนุมัติเสมอ
3. **"กฎแห่งกรรมดิจิทัล" เป็นกรอบคิดของ Lead** ไม่ใช่ข้อกำหนดในเอกสารเดิม ผมแปลเป็นกลไกที่ตรวจสอบได้: เหตุ (การกระทำ) → หลักฐาน (บันทึกต่อท้ายอย่างเดียว) → ผล (สิทธิ์/ความไว้วางใจ) → ทบทวน (อุทธรณ์/แก้ไข) การบอกว่า "ยุติธรรมกว่า" ต้องพิสูจน์ด้วยกติกาที่ชุมชนรับรองและการตรวจอิสระ ยังไม่ใช่ข้อเท็จจริง
4. กลไกความเป็นธรรมที่นำมาแสดงมีที่มาจากเอกสาร: รีวิวต้องมีธุรกรรมที่ยืนยันแล้ว, กักค่าผิดปกติ (เกิน 2 SD), จำกัดความถี่, กลไกอุทธรณ์ (doc 160 ส่วนความเสี่ยง Social Mirror) แต่ **ยังเป็นสเปก** ไม่มีโค้ดตรวจพบ
5. ตัวอย่างลูกค้า/ใบเสนอราคาเป็นเรื่องสมมติ

## 2. อุปกรณ์สามตัวและบทบาท
| อุปกรณ์ | บทบาท | ทำอะไร | ทำอะไรไม่ได้ |
|---|---|---|---|
| นาฬิกา/KeySign | ยืนยันตัวตน | อนุมัติงานย้อนกลับไม่ได้ด้วยการกดค้าง (PKT-R5) | ไม่เก็บงานหรือบทสนทนา |
| โทรศัพท์ | ผู้ช่วยพกพา | สรุปเช้า สั่งด้วยเสียง แจ้งเตือน ดูสถานะ ทำร่างออฟไลน์ | **อนุมัติงานเสี่ยงแทนเจ้าของไม่ได้** |
| โน้ตบุ๊ก/แท็บเล็ต | งานเชิงลึก | บทสนทนา แผน ผลลัพธ์ บันทึกหลักฐาน | อนุมัติเองไม่ได้ ต้องไปยืนยันที่นาฬิกา |

## 3. องค์ประกอบมาตรฐานของ Harness และเอกลักษณ์ SPADA
| องค์ประกอบมาตรฐาน | ในแบบ SPADA |
|---|---|
| บทสนทนา | ข้อความเจ้าของ/MyAI คงเดิม |
| แผนงานเป็นขั้น | แผน 5 ขั้น ติดป้ายสีความเสี่ยง (เขียวย้อนกลับได้ / แดงย้อนกลับไม่ได้) |
| การเรียกเครื่องมือ | แสดงสถานะ (รอ/ทำ/เสร็จ/รออนุมัติ) และการได้รับอนุญาต (consent) |
| ขออนุมัติ (permission prompt) | การ์ดทอง + บังคับยืนยันที่อุปกรณ์ + ไม่มีปุ่มอนุมัติบนหน้าจอ |
| บันทึกกิจกรรม | **ด้ายกรรม** แถบด้านขวา: แต่ละการกระทำเป็นปมพร้อม hash ต่อกันเป็นเส้นเดียว |
| ระดับอิสระ | แถบ "อิสระตามประเภทงาน" แยกต่อประเภท ไม่ใช่ระดับเดียวทั้งระบบ |
| ความจำ/บทเรียน | การ์ด "บันทึกบทเรียน" เมื่อมีความผิดพลาด |
| เอกลักษณ์ | **วงโคจร 5 ชั้น** (Place · Space · Service · BookChain · MyAI) เป็นแถบเมนูซ้ายและฉากหลัง, วงแหวน TrustScore, การ์ดชื่อเสียงพกพา |

## 4. เส้นทางการใช้งานในวิดีโอ
เช้า (โทรศัพท์สรุป + สั่งด้วยเสียง) → แผน 5 ขั้นบนโน้ตบุ๊ก → ขั้นที่ย้อนกลับไม่ได้หยุดรออนุมัติ → เตือนบนโทรศัพท์ → กดค้างยืนยันที่นาฬิกา → บันทึกหลักฐานและผล → กรณีผิดพลาด (บทเรียน + ลดอิสระเฉพาะประเภทชั่วคราว) → ข้ามอุปกรณ์/ออฟไลน์ → ชื่อเสียงพกพา

## 5. ข้อเสนอเรื่อง "ความยุติธรรม" (ต้องให้ชุมชนตัดสิน)
1. **กติกาเดียวกันทุกฝ่าย** (เจ้าของ MyAI ผู้ให้บริการ) และกติกาเป็นสาธารณะ
2. **ผิดพลาดแก้ได้:** ลดอิสระเฉพาะประเภท ชั่วคราว ฟื้นเมื่อทำถูกซ้ำ ไม่ลงโทษเกินเหตุ
3. **กันการแกล้ง:** รีวิวต้องมีหลักฐานธุรกรรม, กักค่าผิดปกติ, จำกัดความถี่
4. **อุทธรณ์ด้วยหลักฐาน** (ต้องกำหนดว่าอุทธรณ์ที่ใคร ภายในเวลาเท่าไร)
5. **ความเสี่ยงที่ต้องออกแบบรับมือ:** การเล่นระบบคะแนน (gaming), อคติเชิงระบบ, การสร้างแรงกดดันทางสังคมจากคะแนน (ดู doc 160 ข้อ 7)
