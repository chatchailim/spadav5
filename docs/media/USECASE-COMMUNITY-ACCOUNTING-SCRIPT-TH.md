# บทวิดีโอ Use Case: ชุมชน และสำนักงานบัญชี (SPADA DID → OneManOS SetBox)

**รหัสเอกสาร:** SPD-MED-003 · **สถานะ:** ร่างเพื่อทบทวน (ยังไม่ผ่านผู้ตรวจที่ไม่ใช่ผู้เขียน และยังไม่ได้รับอนุมัติจากเจ้าของโครงการ) · **วันที่:** 2026-10-02
**เกี่ยวข้อง:** SPD-MED-002 (แผนวิดีโอสั้น)

## 1. ข้อมูลการผลิตและข้อกำกับ
- 2 คลิปแนวตั้ง 1080×1920 / 30 fps: Use Case 1 ชุมชน (91 วินาที), Use Case 2 สำนักงานบัญชี (131 วินาที) เสียง Gemini TTS (Puck) คำบรรยายฝังบนภาพ
- **ทุกตัวอย่างเป็นเรื่องสมมติ** ไม่มีลูกค้าหรือผู้ใช้จริง (ดู INVESTOR-CLAIM-REGISTER: INV-C26 ไม่มีผู้ใช้/LOI) ป้ายกำกับบนจอทุกฉาก: "เรื่องสมมติเพื่ออธิบาย · สร้างโดยเอไอ · ช่วงทดลอง"
- ความสามารถทุกข้อบรรยายเป็น "แนวคิด/เป้าหมายการออกแบบ" ไม่ใช่ผลที่พิสูจน์แล้ว ไม่ใส่ตัวเลขผลลัพธ์หรือการลงทุน ไม่ใช่คำแนะนำด้านบัญชี ภาษี หรือกฎหมาย
- KeySign ระบุว่ายังอยู่ระหว่างพัฒนา การเปิดเผยเฉพาะที่จำเป็น (selective disclosure/ZK) ระบุเป็นเป้าหมายการออกแบบ (PROP-0002 ยังต้องยืนยัน)

## 2. แหล่งอ้างอิง (ตรวจกับต้นทางก่อนเผยแพร่)
| ประเด็น | ต้นทาง |
|---|---|
| DID เป็นตัวตนพกพา ไม่ผูกผู้ให้บริการ, KeySign เป็น root of trust | PROP-0002, ADR 0008 (ตาม CURRENT-STATE) |
| 5 ชั้น: Place (DID/สิทธิ์/consent) → Space → Service → BookChain (append-only) → MyAI | CURRENT-STATE |
| โหนดชุมชนแบบสมาคม/สหกรณ์, Steward ช่วยผู้ไม่มีอุปกรณ์ | MEMBER-ECONOMY (M9 และหัวข้อโหนดชุมชน) |
| ระบบนอก SPADA ใช้รหัสท้องถิ่นแล้วผูก DID ผ่าน OIDC | ADR 0022 |
| ผู้ช่วยเอไอไม่มี DID ทำภายใต้ใบรับรองผู้กระทำที่เจ้าของลงนาม | ADR 0016 |
| อัตโนมัติเฉพาะงานย้อนกลับได้, ด่านมนุษย์ระบุชื่อ | D2.1, ADR 0014 |

## 3. บทรายฉาก

### Use Case 1 · ชุมชน

**ฉาก 1** — จอ: *คุณมีตัวตน ดิจิทัลกี่แห่ง* (แอปธนาคาร · แพลตฟอร์ม · บัญชีสมาชิก)

> ลองนับดูสิ คุณมีบัญชีกี่แห่ง แอปธนาคาร แพลตฟอร์มซื้อของ บัญชีสมาชิกร้านค้า แต่ละที่เก็บข้อมูลของคุณคนละชุด และเป็นของผู้ให้บริการ ไม่ใช่ของคุณ

**ฉาก 2** — จอ: *ตัวตนดิจิทัล ที่เป็นของคุณเอง* (คุณ · SPADA DID · บริการต่างๆ)

> แนวคิดของสปาดา คือให้คุณมีตัวตนดิจิทัลของตัวเอง เรียกว่า ดีไอดี พกไปใช้กับบริการต่างๆ ได้ ไม่ผูกติดกับผู้ให้บริการรายใดรายเดียว

**ฉาก 3** — จอ: *พิสูจน์ว่า เป็นคุณจริง* (กุญแจฮาร์ดแวร์ · KeySign · กำลังพัฒนา)

> การยืนยันว่าเป็นคุณจริง ใช้กุญแจที่เป็นอุปกรณ์ฮาร์ดแวร์ ชื่อ คีย์ไซน์ ส่วนนี้ยังอยู่ระหว่างพัฒนาและทดสอบ ไม่ใช่สิ่งที่ใช้ได้แล้ววันนี้

**ฉาก 4** — จอ: *คุณเป็นคนเลือก ว่าจะให้ดูอะไร* (ให้ความยินยอม — เลือกบริการที่จะเปิดข้อมูล · เปิดเฉพาะที่จำเป็น — เป้าหมายของการออกแบบ)

> หลักคิดคือ คุณเป็นคนให้ความยินยอม ว่าบริการไหนดูข้อมูลอะไรได้ และออกแบบให้เปิดเฉพาะเท่าที่จำเป็น ซึ่งเป็นเป้าหมายของการออกแบบ ยังต้องพิสูจน์ในการใช้งานจริง

**ฉาก 5** — จอ: *ตัวอย่างสมมติ สหกรณ์ชุมชน* (สมาชิก · โหนดชุมชน · บริการชุมชน)

> ลองนึกถึงสหกรณ์ชุมชนสมมติแห่งหนึ่ง เป็นโหนดชุมชนที่บริหารแบบสมาคม สมาชิกใช้ตัวตนเดียว เข้าบริการของชุมชน ทั้งทะเบียนสมาชิก การจองอุปกรณ์ส่วนกลาง และการลงคะแนนในที่ประชุม

**ฉาก 6** — จอ: *คนที่ไม่ถนัด เทคโนโลยีล่ะ* (ผู้สูงอายุ · ผู้ไม่มีอุปกรณ์ · อาสาช่วยเข้าใช้)

> แล้วผู้สูงอายุหรือคนที่ไม่มีมือถือล่ะ แนวคิดของเราคือมีอาสาสมัครในชุมชน ที่ผ่านการอบรม ช่วยพาเข้าใช้บริการ โดยผู้ใช้ยังเป็นคนให้ความยินยอมเอง

**ฉาก 7** — จอ: *ทุกอย่าง ตรวจย้อนหลังได้* (ใครทำ · ทำอะไร · เมื่อไร)

> ทุกการกระทำบันทึกลงบันทึกหลักฐานแบบเพิ่มต่อท้ายอย่างเดียว ลบย้อนหลังไม่ได้ สมาชิกจึงตรวจได้ว่าใครทำอะไร และเมื่อไร ชุมชนไม่ต้องเชื่อกันด้วยคำพูดอย่างเดียว

**ฉาก 8** — จอ: *ความจริงตอนนี้* (มีแล้ว — แบบสถาปัตยกรรมและการทดลอง · ยังไม่มี — ผู้ใช้จริงจำนวนมาก)

> พูดตรงๆ ตอนนี้ยังอยู่ในช่วงทดลอง เรามีแบบสถาปัตยกรรมและการทดลองบางส่วน แต่ยังไม่มีผู้ใช้จริงจำนวนมาก ตัวอย่างสหกรณ์ในคลิปเป็นเรื่องสมมติเพื่ออธิบาย ชุมชนของคุณอยากได้บริการอะไร คอมเมนต์บอกเราได้


### Use Case 2 · สำนักงานบัญชี

**ฉาก 1** — จอ: *สำนักงานบัญชี ลูกค้าหลายสิบราย* (เอกสารในแชต · อีเมล · โต๊ะทำงาน)

> สมมติมีสำนักงานบัญชีแห่งหนึ่ง ดูแลลูกค้าหลายสิบราย เอกสารมาจากแชต อีเมล และกองกระดาษบนโต๊ะ ช่วงปลายเดือนทีมแทบไม่ได้หายใจ

**ฉาก 2** — จอ: *เอกสารลูกค้า อ่อนไหวมาก* (ใครแก้อะไร · ใครเห็นข้อมูล · ตามย้อนยาก)

> ที่น่ากังวลกว่านั้นคือ เอกสารบัญชีเป็นข้อมูลอ่อนไหว ใครแก้ตรงไหน ใครเห็นข้อมูลลูกค้ารายไหน ถ้าตามย้อนหลังไม่ได้ ก็เสี่ยงทั้งความผิดพลาดและความไว้วางใจ

**ฉาก 3** — จอ: *ขั้น 1 พนักงานมี DID* (พนักงาน · SPADA DID · บทบาทในบริษัท)

> ขั้นแรก พนักงานแต่ละคนมีตัวตนดิจิทัลของตัวเอง คือ ดีไอดี และบริษัทผูกบทบาทให้ เช่น ผู้จัดทำบัญชี ผู้สอบทาน หรือผู้อนุมัติ ทุกคนจึงรู้ว่าใครมีอำนาจทำอะไร

**ฉาก 4** — จอ: *ขั้น 2 ติดตั้งเซ็ตบ็อกซ์* (บริษัท · เซ็ตบ็อกซ์ · ผู้ช่วยเอไอ)

> ขั้นสอง บริษัทตั้งเซ็ตบ็อกซ์ เป็นกล่องทำงานของบริษัท ผู้ช่วยเอไอทำงานอยู่ข้างในนี้ ภายใต้ขอบเขตที่บริษัทกำหนดไว้ ไม่ใช่ปล่อยให้เข้าถึงทุกอย่าง

**ฉาก 5** — จอ: *เอไอช่วยงานซ้ำ ที่ย้อนกลับได้* (จัดหมวดเอกสาร · ร่างสมุดรายวัน · ตรวจความครบ)

> งานที่ย้อนกลับได้ เช่น จัดหมวดเอกสาร ร่างรายการสมุดรายวัน และตรวจว่าเอกสารครบหรือยัง ผู้ช่วยเอไอทำเองได้ นักบัญชีเหลือเวลาไปทำงานที่ต้องใช้วิจารณญาณ

**ฉาก 6** — จอ: *เห็นเฉพาะ ลูกค้าที่ได้รับมอบ* (ผู้ช่วยตัวที่ 1 — ลูกค้ากลุ่ม ก · ผู้ช่วยตัวที่ 2 — ลูกค้ากลุ่ม ข)

> ผู้ช่วยแต่ละตัวได้สิทธิ์เท่าที่งานต้องใช้ ตัวที่ดูแลลูกค้ากลุ่มหนึ่ง ก็ไม่เห็นข้อมูลของลูกค้าอีกกลุ่ม ถ้าเกิดอะไรรั่ว ความเสียหายจะจำกัดอยู่ในขอบเขตเดียว

**ฉาก 7** — จอ: *งานย้อนกลับไม่ได้ ต้องมีคนอนุมัติ* (ปิดงบ / ยื่นแบบ · นักบัญชีระบุชื่อ · จึงส่ง)

> แต่ถ้าเป็นงานที่ย้อนกลับไม่ได้ เช่น ยื่นแบบภาษี ปิดงบ หรือโอนเงิน เอไอทำเองไม่ได้ ต้องให้นักบัญชีที่มีชื่อเป็นคนอนุมัติ และผู้ช่วยเอไอไม่มีตัวตนของตัวเอง ต้องทำภายใต้ใบรับรองของเจ้าของ

**ฉาก 8** — จอ: *คนตรวจ ไม่ใช่คนทำ* (ผู้จัดทำ — ทำรายการ · ผู้สอบทาน — ตรวจอีกชั้น)

> หลักเดียวกับงานบัญชีจริง คือผู้จัดทำกับผู้สอบทานต้องเป็นคนละคน เมื่อผู้ช่วยเอไอจัดทำ นักบัญชีหรือผู้ช่วยอีกตัวทำหน้าที่สอบทาน แล้วบันทึกผลไว้

**ฉาก 9** — จอ: *ตรวจย้อนหลัง ได้ทุกขั้น* (ใครทำ · ใครอนุมัติ · เมื่อไร)

> ทุกขั้นตอนมีบันทึก ว่าใครทำ ใครอนุมัติ เมื่อไร ถ้าลูกค้าหรือผู้สอบบัญชีถามว่าตัวเลขนี้มาจากไหน สำนักงานเปิดหลักฐานให้ดูได้ทันที

**ฉาก 10** — จอ: *ผลที่ตั้งเป้า ยังไม่ใช่ผลที่พิสูจน์* (งานซ้ำลดลง · ความผิดพลาดตามได้ · ลูกค้าไว้ใจขึ้น)

> สิ่งเหล่านี้คือผลที่เราตั้งเป้าจากการออกแบบ ได้แก่ งานซ้ำน้อยลง ความผิดพลาดตามรอยได้ และลูกค้าไว้วางใจมากขึ้น แต่ยังไม่มีตัวเลขจากการใช้งานจริงมายืนยัน เราจึงไม่ขอระบุตัวเลขใดๆ

**ฉาก 11** — จอ: *พูดให้ครบ* (เรื่องสมมติ — ไม่ใช่ลูกค้าจริง · ไม่ใช่คำแนะนำ — ด้านบัญชี ภาษี กฎหมาย)

> ขอย้ำว่าสำนักงานบัญชีในคลิปเป็นเรื่องสมมติ ไม่ใช่ลูกค้าจริง และไม่ใช่คำแนะนำด้านบัญชี ภาษี หรือกฎหมาย ระบบยังอยู่ในช่วงทดลอง และข้อมูลภาษีต้องผ่านผู้เชี่ยวชาญเสมอ

**ฉาก 12** — จอ: *คุณทำธุรกิจอะไร* (คอมเมนต์บอกเรา)

> ถ้าคุณทำงานบัญชี หรือธุรกิจบริการอื่น อยากให้ผู้ช่วยเอไอทำงานไหนแทน และงานไหนที่ต้องให้คนตัดสินใจเสมอ คอมเมนต์บอกเราได้เลย

## 4. ก่อนเผยแพร่
1. ผู้ตรวจที่ไม่ใช่ผู้เขียนฟังตรวจคำอ่านผิด (เช่น ดีไอดี คีย์ไซน์ เซ็ตบ็อกซ์)
2. Lead อนุมัติ โดยเฉพาะข้อความเรื่อง DID/KeySign ที่ยังเป็นแนวคิด
3. ขออนุญาตก่อนเอ่ยชื่อบุคคลหรือองค์กรจริง และตรวจข้อกำหนดโฆษณาของแพลตฟอร์ม
4. ไฟล์วิดีโอไม่เก็บใน repo ห้ามเก็บคีย์ API ในเอกสาร
